# 表膨胀

表膨胀是 PostgreSQL 运维里很常见的现象。它通常来自频繁更新、删除后留下的旧版本和空洞。

## 你学完能干什么

- 知道表膨胀为什么会出现
- 能理解 VACUUM 和表膨胀的关系
- 能区分“空间可复用”和“文件变小”
- 知道什么时候该进一步排查 autovacuum

## 为什么会膨胀

PostgreSQL 使用多版本并发控制。更新一行时，旧版本不会立刻原地消失；删除一行时，也需要等没有事务再需要它之后才能清理。

`VACUUM` 可以清理不再需要的旧版本，让空间在表内部复用。但这不一定马上让磁盘文件变小。

## 一个简化过程

| 操作 | 表里发生什么 |
| --- | --- |
| 插入 100 万行 | 文件变大 |
| 删除 50 万行 | 旧行先留下等待清理 |
| VACUUM | 空间可被后续写入复用 |
| 长期频繁更新 | 如果清理跟不上，膨胀可能加重 |

## 排查方向

- 是否有长事务阻止清理
- autovacuum 是否太慢或太少
- 表是否频繁更新大字段
- 索引是否也膨胀
- 是否需要调整维护窗口

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 表膨胀 | 表文件里有很多暂时不能有效利用的空间 |
| VACUUM | 清理旧版本，让空间复用 |
| autovacuum | 自动执行清理和统计维护的后台机制 |
| 长事务 | 长时间不结束的事务，可能阻碍清理 |

## 练习题

1. PostgreSQL 更新一行时，旧版本会立刻物理消失吗？
2. 普通 `VACUUM` 一定会让磁盘文件变小吗？
3. 长事务为什么可能加重膨胀？
4. 表膨胀只和表有关，索引完全不会膨胀吗？

::: tip 提示
先把“空间可以复用”和“文件体积变小”分开理解。
:::

::: details 答案
1. 不会。
2. 不一定。
3. 旧版本可能还不能被清理。
4. 不是，索引也可能膨胀。
:::

## 常见坑

- 看到磁盘没变小就以为 VACUUM 没用
- 长事务一直挂着却只调 VACUUM 参数
- 只看表大小，不看索引大小
- 把 `VACUUM FULL` 当成日常轻量操作

## 先记住这三句

- 表膨胀和旧版本有关。
- VACUUM 主要让空间可复用。
- 长事务会让清理变困难。
