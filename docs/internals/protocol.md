# 前后端协议

PostgreSQL 的前后端协议描述客户端和服务器之间怎么说话。平时你通过驱动连接数据库，驱动就在帮你处理这些细节。

## 你学完能干什么

- 知道驱动和服务器之间不是随便传字符串
- 能理解认证、查询、结果返回都属于协议交互
- 知道什么时候需要深入协议层

## 可运行例子

一次最简化的交互可以这样理解：

```text
客户端发起连接
服务器要求认证
客户端提交认证信息
客户端发送 SQL
服务器返回行数据、状态或错误
```

日常开发通常不直接写协议包，而是使用驱动、连接池或命令行工具。

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| 前后端协议 | 客户端和服务器之间的通信规则 |
| SQL | 客户端发给服务器执行的查询语言 |
| 驱动 | 帮应用实现协议交互的库 |
| 连接池 | 管理和复用多个数据库连接 |

## 练习题

1. 认证过程属于协议交互吗？
2. 普通业务应用是否通常需要自己实现 PostgreSQL 协议？
3. 驱动在协议交互里扮演什么角色？

::: tip 提示
协议层像“说话规则”，SQL 是其中一种被传递和执行的内容。
:::

::: details 答案
1. 属于。
2. 通常不需要。
3. 驱动把应用调用转换成 PostgreSQL 能理解的协议交互。
:::

## 常见坑

- 以为数据库连接只是打开一个 TCP 端口
- 把 SQL 语法问题和协议连接问题混在一起
- 自己实现协议前没有评估维护成本

## 先记住这三句

- 驱动负责把应用请求变成协议交互。
- 认证、查询、返回结果都走协议。
- 普通应用优先用成熟驱动。
