# VACUUM 与统计信息

PostgreSQL 更新和删除数据后，需要清理旧版本，也需要维护统计信息。`VACUUM` 和统计信息都和性能稳定有关。

## 你学完能干什么

- 知道为什么更新删除后会有旧版本
- 能理解 `VACUUM` 大概做什么
- 知道统计信息为什么会影响执行计划
- 能把长事务和清理问题联系起来

## VACUUM 做什么

PostgreSQL 使用多版本并发控制。更新或删除数据后，旧版本不会立刻消失，因为可能还有事务需要看到它。

`VACUUM` 会在安全的时候清理不再需要的旧版本，帮助数据库回收空间并保持运行状态健康。

## 统计信息做什么

优化器需要估算一条 SQL 会命中多少数据、走哪条路线更划算。统计信息就是这些估算的依据。

如果数据变化很多，但统计信息没跟上，数据库可能选错执行计划。

## 长事务的影响

长事务一直开着，可能让旧版本不能被清理。表现出来可能是表膨胀、性能变差、磁盘压力增加。

## 图解：清理和统计信息是两条线

```text
UPDATE / DELETE
  |
  +--> 产生旧版本 -> VACUUM 清理
  |
  +--> 数据分布变化 -> ANALYZE 更新统计信息
```

## 为什么会这样

`VACUUM` 主要处理旧版本和空间复用，`ANALYZE` 主要更新数据分布信息。两者都影响性能，但解决的问题不一样。

## 练习题

1. 为什么更新后旧版本不一定马上消失？
2. `VACUUM` 大概负责什么？
3. 统计信息不准可能带来什么问题？
4. 长事务为什么会影响清理？

::: tip 提示
性能不只是索引问题，也和清理、统计信息、事务习惯有关。
:::

::: details 答案
1. 可能还有事务需要看到旧版本。
2. 清理不再需要的旧版本，维护数据库健康。
3. 数据库可能选择不合适的执行计划。
4. 旧版本可能仍被长事务需要，不能安全清理。
:::

## 常见坑

- 只关注 SQL，不关注表膨胀和清理
- 长事务长期存在却不处理
- 数据量大变后不考虑统计信息
- 把 `VACUUM` 和 `ANALYZE` 当成完全相同的事

## 先记住这三句

- PostgreSQL 需要清理旧版本。
- 统计信息影响执行计划。
- 长事务会拖慢清理节奏。
