# 后台进程

PostgreSQL 不只是一个接收 SQL 的进程。它还有一组后台进程负责写盘、清理、检查点、复制等工作。

## 你学完能干什么

- 知道数据库后台也在持续工作
- 能理解为什么 VACUUM、检查点、写盘会影响运行状态
- 能把后台进程和普通连接区分开
- 知道排查问题时要看后台活动

## 常见后台工作

| 工作 | 新手理解 |
| --- | --- |
| checkpointer | 推进检查点，帮助缩短恢复距离 |
| background writer | 提前写回部分脏页 |
| walwriter | 写 WAL 相关数据 |
| autovacuum | 自动清理旧版本、维护统计信息 |
| logical replication worker | 处理逻辑复制相关任务 |

不同版本和配置下具体进程会有差异，新手先理解它们共同负责“让数据库持续健康运行”。

## 一个排查思路

如果系统写入突然变慢，不只看业务 SQL，也要看：

- 是否正在大量检查点写入
- autovacuum 是否跟不上
- WAL 写入是否压力过大
- 复制是否延迟
- 磁盘是否繁忙

## 图解：前台和后台一起工作

```text
应用连接执行 SQL
  |
  v
产生数据变化和 WAL
  |
  +--> walwriter 写 WAL
  +--> background writer 写脏页
  +--> checkpointer 推进检查点
  +--> autovacuum 清理旧版本
```

## 为什么会这样

数据库不能只在用户请求到来时才工作。写盘、清理、复制和统计维护都需要后台持续推进，否则短时间看似正常，时间一长就会出现恢复变慢、表膨胀、复制延迟等问题。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 后台进程 | 数据库内部持续运行的工作进程 |
| 前台连接 | 应用或用户连进来执行 SQL 的连接 |
| 检查点 | 推进恢复参考位置 |
| 自动清理 | 后台自动执行 VACUUM 和统计维护 |

## 练习题

1. autovacuum 主要负责什么？
2. 后台进程只在用户执行 SQL 时才工作吗？
3. 写入变慢时，只看业务 SQL 够吗？
4. checkpointer 和恢复能力有没有关系？

::: tip 提示
数据库运行状态要同时看前台 SQL 和后台工作。
:::

::: details 答案
1. 自动清理旧版本并维护统计信息。
2. 不是，它们会持续工作。
3. 不够。
4. 有关系，它推进检查点，影响恢复参考位置。
:::

## 常见坑

- 只看应用连接，不看后台活动
- 把 autovacuum 当成可有可无
- 写入慢时完全忽略检查点和磁盘压力
- 复制延迟时只查业务 SQL
- 看到后台进程占资源就直接想关闭

## 先记住这三句

- PostgreSQL 后台一直在做维护工作。
- 前台 SQL 和后台进程会互相影响。
- 排查性能要看整体运行状态。
