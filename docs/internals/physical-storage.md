# 物理存储

物理存储解释 PostgreSQL 最终把数据库、表、索引和大字段放在磁盘上的方式。新手先知道“逻辑对象”和“磁盘文件”不是一一等同就够了。

## 你学完能干什么

- 知道表和索引最终会落到磁盘文件
- 能理解为什么不能直接手改数据库数据目录
- 能把 TOAST、表空间、WAL 和物理存储联系起来

## 可运行例子

在 SQL 里你看到的是逻辑对象：

```sql
CREATE TABLE notes (
  id bigserial PRIMARY KEY,
  body text NOT NULL
);
```

在磁盘上，PostgreSQL 会用自己的目录、文件和页结构管理它。你不需要、也不应该绕过数据库进程直接修改这些文件。

## 图解：逻辑对象到物理文件

```text
SQL 里看到：
数据库 -> 模式 -> 表 -> 行

磁盘上管理：
数据目录 -> 数据库 OID 目录 -> 关系文件 -> 数据页
```

## 为什么会这样

PostgreSQL 要同时维护数据、索引、事务可见性、WAL、空闲空间和系统目录。直接手工修改文件会绕开这些机制，破坏一致性。

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| 表 | SQL 里的逻辑数据对象 |
| 数据页 | 数据库存取数据的基本页单位 |
| 数据目录 | PostgreSQL 实例保存数据文件的位置 |
| 表空间 | 把部分对象放到指定存储位置的机制 |
| WAL | 记录变更，用于恢复和复制 |

## 练习题

1. SQL 里的表是否等于一个可以手工编辑的文本文件？
2. 为什么不能直接修改数据库数据目录里的文件？
3. 表空间解决的是哪类问题？

::: tip 提示
物理存储是数据库内部格式，不是给人手工编辑的数据文件。
:::

::: details 答案
1. 不是。
2. PostgreSQL 需要维护页、事务可见性、WAL 和元数据，手工修改会破坏一致性。
3. 控制数据库对象存放到不同存储位置。
:::

## 常见坑

- 直接复制部分数据文件当备份
- 把表空间当成权限隔离方案
- 忽略 WAL，只看表文件大小
- 看到某个大文件就直接删除，导致实例损坏

## 先记住这三句

- 表是逻辑对象，磁盘上由 PostgreSQL 自己管理。
- 不要手工改数据目录文件。
- 可靠备份要走数据库认可的备份方式。
