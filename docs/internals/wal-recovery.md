# WAL 与恢复

WAL 是 PostgreSQL 保证数据可靠的重要机制。新手可以先把它理解成数据库在真正落盘前写下的变更记录。

## 你学完能干什么

- 知道 WAL 大概解决什么问题
- 能理解为什么崩溃后数据库可以恢复
- 能把 WAL 和备份、复制联系起来

## WAL 是什么

WAL 的意思是预写式日志。数据库在修改数据前，会先把变更写进日志。

这样即使系统突然崩溃，PostgreSQL 也能根据日志恢复到一致状态。

## WAL 和备份的关系

备份保存一个时间点的数据。WAL 记录这个时间点之后发生了什么。

持续归档 WAL 后，就有机会恢复到更接近故障前的状态。

## WAL 和复制的关系

复制也会用到 WAL 思路：主库产生变化，从库接收并应用这些变化，从而尽量保持一致。

## 练习题

1. WAL 的中文可以怎么理解？
2. 为什么数据库崩溃后还能恢复？
3. WAL 和备份分别解决什么问题？
4. 复制为什么会和 WAL 有关系？

::: tip 提示
先把 WAL 理解成“数据库修改的流水账”，之后再深入细节。
:::

::: details 答案
1. 预写式日志。
2. 因为已经记录了变更日志，可以据此恢复一致状态。
3. 备份保存数据快照，WAL 记录后续变化。
4. 从库需要接收并应用主库变化，WAL 正是变化记录的核心来源。
:::

## 常见坑

- 以为有 WAL 就不需要备份
- 忽略 WAL 归档，导致无法按预期恢复
- 把崩溃恢复和人为误删恢复混成一件事

## 先记住这三句

- WAL 是可靠性的基础机制。
- WAL 不能替代备份。
- 恢复能力要靠备份和 WAL 一起设计。
