# 缓冲区与缓存

PostgreSQL 会把常用数据页放在内存缓冲区里，减少反复读磁盘。理解这一点，有助于新手解释“第二次查询为什么更快”。

## 你学完能干什么

- 知道共享缓冲区大致做什么
- 能理解缓存命中和磁盘读取的差异
- 知道缓存不是数据正确性的唯一保障
- 能避免只凭一次查询时间判断性能

## 基本概念

PostgreSQL 读取表或索引时，通常以数据页为单位。需要的数据页可能来自：

- PostgreSQL 的共享缓冲区
- 操作系统缓存
- 磁盘

如果数据已经在内存里，读取会更快；如果必须从磁盘读，成本通常更高。

## 一个现象

同一条查询第一次执行较慢，第二次变快，可能是因为相关数据页已经进入缓存。

这不代表 SQL 一定已经优化好了。要判断性能，仍然需要结合执行计划、数据量和真实访问模式。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 共享缓冲区 | PostgreSQL 自己管理的一块缓存 |
| 操作系统缓存 | 操作系统帮忙缓存文件数据 |
| 缓存命中 | 需要的数据已经在内存里 |
| 磁盘读取 | 需要从磁盘拿数据 |

## 练习题

1. 第二次查询变快，一定是 SQL 改好了吗？
2. 共享缓冲区主要缓存什么？
3. 缓存命中通常比磁盘读取快还是慢？
4. 判断慢查询只看一次执行时间够吗？

::: tip 提示
性能判断要结合缓存状态和执行计划，不要只看一次耗时。
:::

::: details 答案
1. 不一定，可能只是缓存命中了。
2. 表和索引等数据页。
3. 通常更快。
4. 不够。
:::

## 常见坑

- 只跑第二次查询，就以为性能没问题
- 忽略冷缓存和热缓存差异
- 把缓存当成可以替代索引设计
- 只调内存，不看 SQL 和数据访问模式

## 先记住这三句

- 缓存让常用数据读得更快。
- 快一次不代表 SQL 没问题。
- 缓存、索引、执行计划要一起看。
