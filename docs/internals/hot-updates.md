# HOT 更新

HOT 更新是 PostgreSQL 在某些更新场景下减少索引维护成本的优化。新手先理解：不是所有更新都需要改索引。

## 你学完能干什么

- 知道 HOT 更新和索引维护有关
- 能理解为什么更新非索引列可能更轻
- 知道表空间余量会影响更新表现
- 能把频繁更新字段和索引设计联系起来

## 为什么有 HOT

如果一条更新没有改变任何被索引引用的列，PostgreSQL 有机会在同一个表页里放新版本，并避免更新索引项。

这可以减少索引膨胀和写入成本。

但它不是总能发生。是否能 HOT 更新，会受到页内空间、索引列变化等因素影响。

## 一个直觉例子

表 `users` 有索引：

```sql
CREATE INDEX idx_users_email ON users (email);
```

更新 `last_seen_at`：

```sql
UPDATE users
SET last_seen_at = now()
WHERE id = 1;
```

如果 `last_seen_at` 没有被索引引用，这类更新更有机会避免改某些索引。

## 图解：更新索引列和非索引列

```text
更新非索引列：
表里产生新版本 -> 索引可能仍指向同一条 HOT 链

更新索引列：
表里产生新版本 -> 索引也要新增或调整入口
```

## 为什么会这样

索引保存的是帮助定位行版本的信息。如果被索引的值没变，PostgreSQL 在满足条件时可以少维护索引；如果索引列变了，索引也必须反映新值。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| HOT | 堆内元组更新优化 |
| 索引列 | 被索引引用的列 |
| 表页 | 表数据存放的页面 |
| 填充因子 | 表页预留空间的设置 |

## 练习题

1. HOT 更新和索引维护有没有关系？
2. 更新被索引列更容易触发索引维护吗？
3. HOT 更新是否每次更新都一定发生？
4. 频繁更新字段是否要谨慎加索引？

::: tip 提示
字段是否经常更新，会影响你是否应该给它建索引。
:::

::: details 答案
1. 有。
2. 是。
3. 不是。
4. 是。
:::

## 常见坑

- 给频繁更新字段随意加索引
- 以为所有更新成本一样
- 不关注表和索引膨胀
- 只看查询速度，不看写入成本
- 给高频更新时间字段建索引前，没有确认查询是否真的需要

## 先记住这三句

- HOT 更新能减少部分索引维护。
- 更新索引列通常更贵。
- 索引设计要同时看读和写。
