# 索引访问方法

PostgreSQL 有多种索引访问方法。新手先掌握 B-tree 是最常见默认选择，再知道其他索引用于特殊场景。

## 你学完能干什么

- 知道 B-tree 是最常见索引类型
- 能理解不同索引适合不同查询
- 知道全文检索、数组、范围查询可能需要特殊索引
- 不会只凭字段类型盲目选索引

## 常见索引方向

| 访问方法 | 常见用途 |
| --- | --- |
| B-tree | 等值、范围、排序，最常见 |
| GIN | 数组、JSONB、全文检索等多值内容 |
| GiST | 范围、几何、相似性等场景 |
| BRIN | 很大且按物理顺序相关的数据 |
| Hash | 等值查询，但使用场景相对更窄 |

## B-tree 为什么常见

很多查询都属于等值、范围或排序：

```sql
SELECT *
FROM notes
WHERE user_id = 10
ORDER BY created_at DESC;
```

这类场景经常先考虑 B-tree 或组合 B-tree 索引。

## 特殊索引要看查询

如果查询 JSONB、数组或全文检索，可能会看到 GIN。  
如果是超大历史表，并且数据和物理顺序相关，可能会看到 BRIN。

不要只因为某个索引听起来高级就使用它。

## 图解：索引类型先看查询

```text
WHERE user_id = 10 ORDER BY created_at
  -> 常先看 B-tree

WHERE tags @> ARRAY['sql']
  -> 可能看 GIN

WHERE during && tstzrange(...)
  -> 可能看 GiST

超大日志表按时间追加
  -> 可能看 BRIN
```

## 为什么会这样

不同索引访问方法擅长回答的问题不同。索引不是越高级越好，而是越贴合查询条件、操作符和数据分布越好。

## 练习题

1. 最常见的索引访问方法是什么？
2. JSONB 和数组查询可能会考虑哪类索引？
3. BRIN 适合什么样的大表？
4. 选择索引时应该先看字段名还是查询方式？

::: tip 提示
索引类型服务查询模式，不是装饰表结构。
:::

::: details 答案
1. B-tree。
2. GIN。
3. 很大且数据和物理顺序有相关性的大表。
4. 查询方式。
:::

## 常见坑

- 所有索引都默认只理解成 B-tree
- 为了 JSONB 建索引，却不看实际查询操作符
- 听说 BRIN 省空间就盲目使用
- 查询条件变了，索引策略却一直不复查

## 先记住这三句

- B-tree 最常见。
- 特殊索引服务特殊查询。
- 选索引先看查询条件和操作符。
