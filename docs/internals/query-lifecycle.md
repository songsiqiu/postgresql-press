# 查询是怎么执行的

这一页用新手能理解的方式解释：一条 SQL 从发给 PostgreSQL 到返回结果，中间大概经历了什么。

## 你学完能干什么

- 能知道 SQL 不是直接“立刻查表”
- 能理解解析、规划、执行的大致顺序
- 能把执行计划和真实查询过程联系起来

## 一条查询的大致过程

1. 客户端发送 SQL
2. PostgreSQL 解析 SQL
3. 检查对象和权限
4. 生成执行计划
5. 按计划读取数据
6. 返回结果给客户端

## 一个例子

```sql
SELECT id, title
FROM notes
WHERE user_id = 10
ORDER BY created_at DESC
LIMIT 20;
```

PostgreSQL 要先理解这条 SQL 的结构，再判断 `notes` 表是否存在、当前用户有没有权限，接着决定是扫表还是走索引，最后取出结果。

## 练习题

1. 查询执行前，数据库为什么要检查权限？
2. 执行计划在哪一步生成？
3. 为什么同一条 SQL 在数据量变大后可能变慢？

::: tip 提示
把 SQL 执行想成“读懂语句 -> 选路线 -> 按路线干活”。
:::

::: details 答案
1. 防止没有权限的用户读取或修改数据。
2. 在真正读取数据之前。
3. 数据量、索引和统计信息变了，执行成本也会变。
:::

## 常见坑

- 以为 SQL 写出来后数据库只会按一种方式执行
- 忽略权限检查
- 不看执行计划就判断性能原因

## 先记住这三句

- SQL 会先被理解，再被执行。
- 执行计划是数据库选择的路线。
- 数据变了，路线也可能变。
