# 标识符与命名

标识符就是数据库对象的名字，比如表名、列名、模式名和函数名。命名看起来小，但会影响长期维护。

## 你学完能干什么

- 知道表名、列名这些都属于标识符
- 能理解大小写折叠和双引号的影响
- 能选择更稳定的新手命名方式
- 能避免给对象起难维护的名字

## 最小规则

PostgreSQL 里，不加双引号的标识符会被折叠成小写。

```sql
CREATE TABLE UserNotes (
  NoteId bigint
);
```

实际引用时更接近：

```sql
SELECT noteid
FROM usernotes;
```

如果用了双引号，就必须按原样引用：

```sql
CREATE TABLE "UserNotes" (
  "NoteId" bigint
);

SELECT "NoteId"
FROM "UserNotes";
```

新手更推荐使用小写加下划线，比如 `user_notes`、`note_id`。

## 常见命名建议

| 场景 | 建议 |
| --- | --- |
| 表名 | 小写加下划线，表达业务对象 |
| 列名 | 小写加下划线，避免缩写过度 |
| 索引名 | 包含表名和字段名 |
| 约束名 | 能看出约束对象和含义 |

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 标识符 | 数据库对象的名字 |
| 关键字 | SQL 语言保留或常用的词 |
| 双引号标识符 | 强制保留大小写和特殊字符的名字 |
| 小写下划线 | 最常见、最省心的命名风格 |

## 练习题

1. 表名、列名这类名字统称为什么？
2. 不加双引号的 `UserNotes` 通常会被折叠成什么？
3. 新手命名更推荐 `user_notes` 还是 `"UserNotes"`？
4. 为什么不建议滥用双引号标识符？

::: tip 提示
如果没有特别理由，统一使用小写加下划线。
:::

::: details 答案
1. 标识符。
2. `usernotes`。
3. `user_notes`。
4. 之后每次引用都要精确写双引号和大小写，维护更麻烦。
:::

## 常见坑

- 用了双引号后忘记每次都要双引号引用
- 表名和列名大小写风格混乱
- 使用 SQL 关键字当对象名
- 索引和约束名字看不出用途

## 先记住这三句

- 标识符就是对象名字。
- 小写加下划线最省心。
- 双引号能保留大小写，也会增加维护成本。
