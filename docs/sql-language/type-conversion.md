# 类型转换

类型转换让一个值从一种类型变成另一种类型。它很常见，但隐式转换太多会让 SQL 难懂，也可能影响索引使用。

## 你学完能干什么

- 能看懂显式类型转换写法
- 知道隐式转换为什么可能带来问题
- 能把字符串转换成日期、数字等类型
- 能避免把类型问题留给数据库猜

## 常见写法

```sql
SELECT '123'::integer;
```

也可以写成：

```sql
SELECT CAST('123' AS integer);
```

日期时间也经常需要明确类型：

```sql
SELECT TIMESTAMPTZ '2026-05-16 10:00:00+08';
```

## 隐式转换

有时 PostgreSQL 会根据上下文自动转换类型。但新手不应该依赖“数据库帮我猜”。当类型会影响结果或性能时，最好写清楚。

例如，字段是数字，就不要长期用字符串参数模糊比较。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 显式转换 | 你明确写出要转成什么类型 |
| 隐式转换 | 数据库根据上下文自动转换 |
| `::` | PostgreSQL 常见类型转换写法 |
| `CAST` | 标准 SQL 类型转换写法 |

## 练习题

1. `'123'::integer` 是显式转换还是隐式转换？
2. `CAST('123' AS integer)` 和 `::integer` 都能表达类型转换吗？
3. 为什么不建议长期依赖隐式转换？
4. 字符串能不能随便转换成任何日期？

::: tip 提示
类型不清楚时，优先写清楚目标类型。
:::

::: details 答案
1. 显式转换。
2. 能。
3. 可读性差，也可能影响执行计划和索引使用。
4. 不能，字符串必须符合可解析的日期格式。
:::

## 常见坑

- 把数字和日期长期当字符串处理
- 依赖隐式转换，导致 SQL 行为不直观
- 转换失败后才发现历史数据格式混乱
- 在索引列上做不必要的类型转换

## 先记住这三句

- 类型转换要写清楚。
- 隐式转换不是越多越方便。
- 字段类型应该和业务语义一致。
