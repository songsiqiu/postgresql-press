# 生成列与表达式

生成列让某一列的值由表达式自动计算。它适合把稳定、可推导的值放在表结构里，减少重复计算或重复存储逻辑。

## 你学完能干什么

- 知道生成列解决什么问题
- 能区分普通列和生成列
- 能判断什么时候不该用生成列
- 知道生成列表达式应该保持简单稳定

## 一个例子

```sql
CREATE TABLE products (
  id bigserial PRIMARY KEY,
  price numeric NOT NULL,
  tax numeric NOT NULL,
  total_price numeric GENERATED ALWAYS AS (price + tax) STORED
);
```

这里 `total_price` 由 `price + tax` 自动计算，不能像普通列那样随便手动写入。

## 适合什么

- 值能从同一行其他列稳定推导
- 需要经常查询这个推导结果
- 希望把计算规则放在数据库结构里

## 不适合什么

- 计算规则经常变化
- 需要跨表查询才能算出来
- 业务含义复杂，放应用层更清楚

## 练习题

1. 生成列的值来自哪里？
2. 生成列适合经常变化的计算规则吗？
3. `total_price` 可以手动随便插入吗？
4. 生成列表达式为什么要简单稳定？

::: tip 提示
生成列适合“同一行里能稳定算出来”的值。
:::

::: details 答案
1. 来自表达式，通常由同一行其他列计算。
2. 不太适合。
3. 不可以，它由数据库计算。
4. 规则复杂或频繁变化会让结构维护变难。
:::

## 常见坑

- 把复杂业务规则塞进生成列
- 需要跨表计算却硬做成生成列
- 规则改动频繁，导致表结构频繁变更

## 先记住这三句

- 生成列是自动计算的列。
- 规则要简单、稳定、可推导。
- 复杂业务计算不一定适合放进表结构。
