# 外连接

外连接让查询在匹配不到另一张表时，也能保留某一边的数据。它常用于“主表要保留，关联信息可有可无”的场景。

## 你学完能干什么

- 能区分内连接和外连接
- 能理解 `LEFT JOIN` 为什么会产生 `NULL`
- 知道外连接条件放错位置会改变结果
- 能写出保留主表数据的查询

## LEFT JOIN

```sql
SELECT u.id, u.name, p.bio
FROM users u
LEFT JOIN profiles p ON p.user_id = u.id;
```

这条 SQL 会保留所有用户。没有资料的用户，`p.bio` 会是 `NULL`。

## 和 INNER JOIN 的区别

| 写法 | 结果 |
| --- | --- |
| `INNER JOIN` | 只保留两边匹配的行 |
| `LEFT JOIN` | 保留左表所有行 |
| `RIGHT JOIN` | 保留右表所有行 |
| `FULL JOIN` | 两边不匹配的也都保留 |

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 内连接 | 只看匹配成功的数据 |
| 外连接 | 允许保留不匹配的数据 |
| 左表 | `LEFT JOIN` 左边的表 |
| 空值 | 另一边没有匹配时补出的 `NULL` |

## 练习题

1. 想保留所有用户，即使没有资料，应该用哪种 JOIN？
2. `LEFT JOIN` 匹配不到右表时，右表字段会是什么？
3. `INNER JOIN` 会保留不匹配的行吗？
4. 外连接条件写错会不会改变结果范围？

::: tip 提示
先问一句：哪张表的数据必须保留。
:::

::: details 答案
1. `LEFT JOIN`。
2. `NULL`。
3. 不会。
4. 会。
:::

## 常见坑

- 把 `LEFT JOIN` 后的右表条件写到 `WHERE`，结果变得像内连接
- 不理解外连接产生的 `NULL`
- 用 `RIGHT JOIN` 让阅读方向变复杂
- 多个外连接叠在一起后不检查结果行数

## 先记住这三句

- 外连接保留不匹配的一边。
- `LEFT JOIN` 最常见。
- 过滤条件位置会影响结果。
