# 集合操作

集合操作用来把多条查询的结果合在一起、取交集或做差集。它适合处理“两个结果集之间是什么关系”的问题。

## 你学完能干什么

- 能区分 `UNION`、`INTERSECT` 和 `EXCEPT`
- 知道 `UNION` 默认会去重
- 能理解集合操作要求列数量和类型匹配
- 能避免把集合操作和普通 `JOIN` 混在一起

## 常见写法

```sql
SELECT email FROM trial_users
UNION
SELECT email FROM paid_users;
```

`UNION` 会合并两边结果，并默认去重。

如果想保留重复行：

```sql
SELECT email FROM trial_users
UNION ALL
SELECT email FROM paid_users;
```

## 三种操作

| 操作 | 新手解释 |
| --- | --- |
| `UNION` | 合并两个结果集 |
| `INTERSECT` | 只保留两边都有的结果 |
| `EXCEPT` | 保留左边有、右边没有的结果 |
| `UNION ALL` | 合并但不去重 |

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 结果集 | 一条查询返回的行集合 |
| 去重 | 删除重复行 |
| 交集 | 两边共同拥有的结果 |
| 差集 | 左边有、右边没有的结果 |

## 练习题

1. 合并两个查询结果常用哪个操作？
2. `UNION` 默认会不会去重？
3. 想保留重复行，应该用什么？
4. `EXCEPT` 表示交集还是差集？

::: tip 提示
先判断你要“合并、共同拥有，还是左边独有”。
:::

::: details 答案
1. `UNION`。
2. 会。
3. `UNION ALL`。
4. 差集。
:::

## 常见坑

- 两边查询列数量不一致
- 以为 `UNION` 会保留重复行
- 把集合操作当成表关联
- 在大结果集上去重却不考虑成本

## 先记住这三句

- 集合操作处理查询结果之间的关系。
- `UNION` 默认去重。
- `UNION ALL` 保留重复行。
