# 大对象

大对象是 PostgreSQL 用来处理很大二进制内容的一套机制。新手先知道：大文件通常更推荐放对象存储或文件系统，数据库只保存引用。

## 你学完能干什么

- 知道大对象解决什么问题
- 能区分大对象和普通 `bytea`
- 理解为什么文件不一定适合直接塞进数据库
- 能避免忽略大对象权限和清理

## 一个直觉例子

如果应用要保存头像、小型附件，可以考虑 `bytea` 或外部存储引用。

如果是很大的文件，直接放数据库会影响备份、恢复、传输和清理成本。大对象机制可以分块处理大内容，但也带来额外管理责任。

## 常见命令入口

在 `psql` 中常见相关命令包括：

```text
\lo_import
\lo_export
\lo_list
```

这些命令主要用于导入、导出和查看大对象。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 大对象 | 数据库内部管理的大型二进制对象 |
| `bytea` | 表字段里保存的二进制数据 |
| 对象存储 | 数据库外部保存文件的服务 |
| 引用 | 表里只保存文件位置或对象 ID |

## 练习题

1. 大文件一定要直接存进 PostgreSQL 吗？
2. `bytea` 是普通字段类型还是数据库外部文件？
3. 大对象会不会带来权限和清理成本？
4. 表里保存文件地址属于保存内容还是保存引用？

::: tip 提示
先问“数据库是否真的应该保存文件本体”，再选 `bytea`、大对象或外部存储。
:::

::: details 答案
1. 不一定，很多场景更适合外部存储。
2. 普通字段类型。
3. 会。
4. 保存引用。
:::

## 常见坑

- 把所有文件都直接塞进数据库
- 只考虑上传方便，不考虑备份恢复变大
- 删除业务记录后忘记清理对应大对象
- 忽略大对象自己的权限管理

## 先记住这三句

- 大对象适合少数明确场景。
- 文件本体和文件引用不是一回事。
- 保存大内容前先想备份、恢复和清理。
