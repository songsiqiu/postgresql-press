# LATERAL 关联

`LATERAL` 让右侧子查询可以引用左侧行。它常用于“每一行都要带着自己的条件去查一小段数据”的场景。

## 你学完能干什么

- 能理解 `LATERAL` 为什么能引用左侧行
- 能看懂“每个用户取最近一条记录”的写法
- 知道它和普通子查询、普通 JOIN 的区别
- 能避免把简单查询写得过度复杂

## 最小例子

```sql
SELECT u.id, u.name, n.title
FROM users u
LEFT JOIN LATERAL (
  SELECT title
  FROM notes n
  WHERE n.user_id = u.id
  ORDER BY n.created_at DESC
  LIMIT 1
) n ON true;
```

这条 SQL 的意思是：对每个用户，找这个用户最新的一条笔记。

## 什么时候有用

- 每个分组取前 1 条或前 N 条
- 子查询需要引用外层当前行
- 对每一行调用返回多行的函数
- 想把复杂关联拆得更清楚

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `LATERAL` | 允许右侧子查询引用左侧行 |
| 外层行 | 当前正在处理的左侧记录 |
| 子查询 | 嵌在 SQL 里的查询 |
| `ON true` | 表示关联条件主要写在子查询内部 |

## 练习题

1. `LATERAL` 右侧子查询能不能引用左侧表的列？
2. 每个用户取最新一条笔记，适合用 `LATERAL` 吗？
3. `LATERAL` 适合替代所有 JOIN 吗？
4. `LIMIT 1` 在上面的例子里有什么作用？

::: tip 提示
看到“每一行都带着自己的条件去查”，就可以想到 `LATERAL`。
:::

::: details 答案
1. 能。
2. 适合。
3. 不适合。
4. 每个用户只取最新一条。
:::

## 常见坑

- 简单 JOIN 也强行写成 `LATERAL`
- 子查询里没有合适排序就 `LIMIT`
- 忽略每行执行子查询可能带来的成本
- `ON true` 让新手误以为没有关联条件

## 先记住这三句

- `LATERAL` 让右侧看到左侧当前行。
- 它适合每行查一小段相关数据。
- 简单关联不要过度使用它。
