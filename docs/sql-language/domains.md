# 域类型

域类型是在已有数据类型上加规则，形成一个可复用的新类型。它适合把通用数据规则沉到数据库层。

## 你学完能干什么

- 知道域类型是带约束的类型
- 能理解它和普通检查约束的关系
- 知道哪些规则适合抽成域类型
- 能避免把域类型用成复杂业务规则容器

## 最小例子

```sql
CREATE DOMAIN positive_amount AS numeric
CHECK (VALUE > 0);
```

之后表里可以使用这个域类型：

```sql
CREATE TABLE invoices (
  id bigserial PRIMARY KEY,
  amount positive_amount NOT NULL
);
```

这样每个使用 `positive_amount` 的地方都会复用“必须大于 0”这个规则。

## 适合场景

- 金额必须为正数
- 邮箱格式有统一基础规则
- 状态码有固定范围
- 多张表都复用同一类字段规则

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 域类型 | 在基础类型上加约束形成的新类型 |
| 基础类型 | `text`、`numeric`、`integer` 这类原有类型 |
| `VALUE` | 域约束中代表当前值 |
| 检查约束 | 要求值满足表达式 |

## 练习题

1. 域类型是在已有类型上加什么？
2. `VALUE` 在域约束里代表什么？
3. 多张表复用同一字段规则时，域类型有没有用？
4. 域类型适合放复杂跨表业务规则吗？

::: tip 提示
域类型适合简单、稳定、可复用的数据规则。
:::

::: details 答案
1. 约束或规则。
2. 当前要检查的值。
3. 有用。
4. 不适合。
:::

## 常见坑

- 把复杂业务流程塞进域类型
- 域规则变动频繁，导致维护困难
- 忽略已有历史数据是否符合新规则
- 域类型命名看不出业务含义

## 先记住这三句

- 域类型是带规则的类型。
- 它适合复用稳定规则。
- 复杂业务不要硬塞进域类型。
