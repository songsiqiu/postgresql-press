# 咨询锁

咨询锁是应用自定义含义的锁。PostgreSQL 只负责加锁和释放锁，不知道这个锁背后的业务含义。

## 你学完能干什么

- 能理解咨询锁和行锁的区别
- 知道咨询锁适合保护应用级资源
- 能看懂事务级咨询锁的基本用法
- 能避免用咨询锁替代数据约束

## 一个例子

```sql
BEGIN;

SELECT pg_advisory_xact_lock(1001);

-- 在这里执行同一个业务资源的关键操作

COMMIT;
```

`pg_advisory_xact_lock` 是事务级咨询锁，事务结束时会自动释放。

## 适合场景

- 同一租户的某个定时任务只能跑一个
- 某个外部资源只能同时被一个流程处理
- 需要跨多张表保护一个业务动作
- 不适合用具体某一行来加锁

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 咨询锁 | 由应用约定含义的锁 |
| 行锁 | 锁具体数据行 |
| 事务级锁 | 事务结束自动释放 |
| 会话级锁 | 连接结束或手动释放才释放 |

## 练习题

1. PostgreSQL 知道咨询锁的业务含义吗？
2. 事务级咨询锁什么时候释放？
3. 咨询锁适合替代唯一约束吗？
4. 咨询锁适合保护应用级资源吗？

::: tip 提示
咨询锁的含义来自应用约定，所以命名和封装要清楚。
:::

::: details 答案
1. 不知道。
2. 事务结束时。
3. 不适合。
4. 适合。
:::

## 常见坑

- 用咨询锁替代数据库约束
- 锁编号没有统一规则
- 会话级锁忘记释放
- 加锁范围太大导致并发下降

## 先记住这三句

- 咨询锁的含义由应用定义。
- 事务级咨询锁更容易管理释放。
- 数据正确性仍优先靠约束。
