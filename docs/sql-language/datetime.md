# 日期与时间

日期时间是业务系统里最容易出错的基础主题。新手先掌握类型选择、时区边界和常见函数，比一开始背完整格式更重要。

## 你学完能干什么

- 能区分 `date`、`time`、`timestamp` 和 `timestamptz`
- 知道什么时候要保存时区相关时间
- 能写出常见的时间筛选条件
- 能避免把时间当普通字符串处理

## 常见类型

| 类型 | 适合场景 |
| --- | --- |
| `date` | 只有日期，比如生日、账单日 |
| `time` | 只有一天中的时间，比如营业开始时间 |
| `timestamp` | 日期和时间，但不带时区语义 |
| `timestamptz` | 日期和时间，并按时区规则解释和显示 |
| `interval` | 一段时间，比如 7 天、3 小时 |

很多应用记录创建时间、支付时间、登录时间时，优先考虑 `timestamptz`，因为它更适合跨时区场景。

## 常见查询

```sql
SELECT id, title, created_at
FROM notes
WHERE created_at >= TIMESTAMPTZ '2026-05-01 00:00:00+08'
  AND created_at <  TIMESTAMPTZ '2026-06-01 00:00:00+08'
ORDER BY created_at DESC;
```

用“左闭右开”的时间范围，比写 `BETWEEN` 更不容易在一天结束、毫秒精度、月末边界上出错。

## 动手区：改时间范围

假设有三条笔记：

| id | created_at |
| --- | --- |
| 1 | 2026-05-01 09:00:00+08 |
| 2 | 2026-05-31 23:59:59+08 |
| 3 | 2026-06-01 00:00:00+08 |

这条 SQL 会返回前两条：

```sql
SELECT id
FROM notes
WHERE created_at >= TIMESTAMPTZ '2026-05-01 00:00:00+08'
  AND created_at <  TIMESTAMPTZ '2026-06-01 00:00:00+08';
```

如果把第二个条件改成 `<= '2026-06-01 00:00:00+08'`，第三条也会被包含进来，这通常不是“查 5 月数据”想要的结果。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `timestamp` | 记录日期时间，但不带时区解释 |
| `timestamptz` | 按时区规则保存和显示时间点 |
| `interval` | 一段持续时间，不是某个具体时刻 |
| 左闭右开 | 包含开始时间，不包含结束时间 |

## 练习题

1. 只保存生日，应该优先考虑哪个类型？
2. 保存登录时间，为什么通常更适合 `timestamptz`？
3. 查询 2026 年 5 月数据时，结束条件建议写 `< 2026-06-01` 还是 `<= 2026-05-31`？
4. `interval '7 days'` 表示具体日期还是一段时间？

::: tip 提示
先判断你要保存的是“日期”“一天中的时间”“具体时间点”还是“一段时间”。
:::

::: details 答案
1. `date`。
2. 登录时间是一个真实发生的时间点，跨时区展示时需要明确语义。
3. 建议写 `< 2026-06-01`。
4. 一段时间。
:::

## 常见坑

- 把时间保存成普通字符串
- 用 `BETWEEN` 查整天数据，漏掉或多包含边界
- 没想清楚是否需要时区语义
- 用业务编号或字符串排序代替真正的时间字段排序

## 先记住这三句

- 时间类型先按业务语义选。
- 查时间范围优先用左闭右开。
- 跨时区系统要认真处理 `timestamptz`。
