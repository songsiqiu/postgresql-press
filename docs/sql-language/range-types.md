# 范围类型

范围类型可以把“一段值”作为一个字段保存，比如会议室占用时间、价格区间、有效日期区间。

## 你学完能干什么

- 知道范围类型适合表达连续区间
- 能看懂 `[`、`]`、`(`、`)` 的边界含义
- 能用重叠、包含这类条件表达业务规则
- 知道范围类型可以配合索引和约束

## 最小例子

```sql
CREATE TABLE reservations (
  id bigserial PRIMARY KEY,
  room_id integer NOT NULL,
  during tstzrange NOT NULL
);

INSERT INTO reservations (room_id, during)
VALUES (101, '[2026-05-16 10:00+08, 2026-05-16 11:00+08)');
```

`[)` 表示包含开始时间，不包含结束时间。这和时间范围查询里的左闭右开是一致的。

## 常见操作

```sql
SELECT *
FROM reservations
WHERE during && tstzrange(
  TIMESTAMPTZ '2026-05-16 10:30+08',
  TIMESTAMPTZ '2026-05-16 11:30+08',
  '[)'
);
```

`&&` 表示两个范围是否有重叠。会议室、排班、促销有效期这类场景很常见。

## 动手区：判断是否冲突

已有预约：

```text
[10:00, 11:00)
```

试着判断下面三个时间段是否冲突：

| 新时间段 | 是否冲突 | 原因 |
| --- | --- | --- |
| `[09:00, 10:00)` | 否 | 正好在开始前结束 |
| `[10:30, 11:30)` | 是 | 和已有预约重叠 |
| `[11:00, 12:00)` | 否 | 正好从结束点开始 |

这就是左闭右开边界的价值：连续时间段可以首尾相接，不会互相误判冲突。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 范围 | 一个起点到终点之间的值集合 |
| 上界 | 范围结束位置 |
| 下界 | 范围开始位置 |
| 重叠 | 两个范围有共同部分 |
| 空范围 | 不包含任何值的范围 |

## 练习题

1. `[3,7)` 是否包含 3？
2. `[3,7)` 是否包含 7？
3. 会议室预约冲突适合用范围类型吗？
4. `&&` 在范围判断里常用来表达什么？

::: tip 提示
看范围时先看边界符号，再判断两个范围有没有共同部分。
:::

::: details 答案
1. 包含。
2. 不包含。
3. 适合。
4. 两个范围是否重叠。
:::

## 常见坑

- 没看清楚边界是包含还是不包含
- 用两个普通字段保存起止时间，却到处手写重叠判断
- 把相邻时间段误判成冲突
- 忘记给高频范围查询配合合适索引

## 先记住这三句

- 范围类型适合表达区间。
- `[)` 是最常见、最稳的时间区间写法。
- 重叠判断比手写多个条件更清楚。
