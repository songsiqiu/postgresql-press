# 序列与身份列

序列和身份列常用于生成自增编号。新手最需要先明白：自增编号不等于业务编号，也不保证一定连续。

## 你学完能干什么

- 知道序列大概做什么
- 能理解身份列和自增主键的关系
- 知道自增值可能有空洞
- 不会把自增主键当业务单号使用

## 身份列例子

```sql
CREATE TABLE demo_users (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name text NOT NULL
);
```

插入数据时不用手动写 `id`：

```sql
INSERT INTO demo_users (name)
VALUES ('Alice');
```

数据库会自动生成编号。

## 为什么编号可能不连续

序列为了性能和并发，不保证值一定连续。事务回滚、缓存、并发插入都可能让编号出现空洞。

这通常不是问题。主键的目标是唯一标识一行，不是生成连续票据号。

## 序列和业务编号

如果业务需要严格连续编号，比如发票号、流水号，要单独设计规则，不要简单依赖自增主键。

## 练习题

1. 身份列常用于生成什么？
2. 自增主键一定连续吗？
3. 业务发票号适合直接用自增主键吗？
4. 主键编号最重要的目标是什么？

::: tip 提示
自增主键服务数据标识，业务编号服务业务规则，不要混用。
:::

::: details 答案
1. 自动生成编号。
2. 不一定。
3. 不适合，需要按业务规则单独设计。
4. 唯一标识一行数据。
:::

## 常见坑

- 看到自增编号跳号就以为数据库坏了
- 把主键当业务单号
- 手动插入身份列值导致序列和数据不一致

## 先记住这三句

- 自增编号不保证连续。
- 主键不是业务单号。
- 身份列让数据库自动生成标识。
