# 分区表基础

分区表用来把一张逻辑大表拆成多个物理分区。它适合数据量很大、访问模式比较明确的场景。

## 你学完能干什么

- 知道分区表解决什么问题
- 能理解范围分区、列表分区的基本思路
- 知道分区不是性能万能药
- 能判断什么时候先不该用分区

## 一个范围分区例子

按月份拆订单：

```sql
CREATE TABLE orders (
  id bigserial,
  created_at date NOT NULL,
  amount numeric NOT NULL
) PARTITION BY RANGE (created_at);

CREATE TABLE orders_2026_05
PARTITION OF orders
FOR VALUES FROM ('2026-05-01') TO ('2026-06-01');
```

这里 `orders` 是逻辑上的父表，`orders_2026_05` 是具体分区。

## 分区适合什么

- 数据量很大
- 经常按时间、地区、类型这类固定维度查询
- 旧数据需要按分区归档或清理
- 查询条件能命中少量分区

## 不适合什么

- 小表
- 查询条件和分区键没关系
- 业务规则还没稳定
- 只是觉得“分区听起来更高级”

## 练习题

1. 分区表是把一张逻辑表拆成什么？
2. 按月份拆订单，常见分区键可能是什么？
3. 小表适合一上来就分区吗？
4. 查询条件不带分区键，分区效果一定好吗？

::: tip 提示
分区先从访问模式出发。没有稳定查询规律，就不要急着分区。
:::

::: details 答案
1. 多个物理分区。
2. `created_at`。
3. 不适合。
4. 不一定，可能仍然需要扫描很多分区。
:::

## 常见坑

- 数据量不大就过早分区
- 分区键选错，查询完全用不上
- 只建父表，忘记规划后续分区维护

## 先记住这三句

- 分区服务大数据量和明确访问模式。
- 分区键选错，收益会很差。
- 分区带来管理成本，不是免费优化。
