# 错误码速查

PostgreSQL 的错误信息通常会带 SQLSTATE。错误码能帮助你判断问题类型，而不是只看一段报错文字。

## 你学完能干什么

- 知道 SQLSTATE 是什么
- 能按错误类型判断处理方向
- 知道哪些错误适合重试，哪些不适合
- 能把错误码和应用错误处理联系起来

## SQLSTATE 是什么

SQLSTATE 是一组标准化错误码。它通常由 5 个字符组成，前两位表示错误大类。

应用记录错误时，最好保留 SQLSTATE。这样后续排查会比只看中文或英文报错更稳定。

## 常见错误类型

| 类型 | 常见含义 | 处理方向 |
| --- | --- | --- |
| 语法错误 | SQL 写错 | 修 SQL |
| 权限错误 | 当前角色不能操作对象 | 查角色和授权 |
| 唯一约束冲突 | 写入了重复值 | 修输入或业务逻辑 |
| 外键约束冲突 | 引用了不存在的数据 | 先保证关联数据存在 |
| 序列化失败 | 并发冲突 | 可以有限重试 |
| 连接异常 | 网络、服务、认证问题 | 查连接和服务状态 |

## 应用里怎么用

应用不要只判断错误文本。更稳的做法是：

1. 记录 SQLSTATE
2. 记录接口或业务动作
3. 判断错误类型
4. 决定返回用户提示、修数据、补权限，还是有限重试

## 练习题

1. SQLSTATE 主要有什么用？
2. 唯一约束冲突应该盲目重试吗？
3. 序列化失败为什么有时可以重试？
4. 为什么不要只按错误文本判断？

::: tip 提示
错误码是分类工具，不是让新手背完整列表。
:::

::: details 答案
1. 帮助稳定判断错误类型。
2. 不应该，通常要修输入或业务逻辑。
3. 它可能来自瞬时并发冲突，稍后重试可能成功。
4. 错误文本可能因语言、版本、包装方式变化，错误码更稳定。
:::

## 常见坑

- 应用吞掉数据库原始错误
- 所有错误都自动重试
- 日志里没有 SQLSTATE
- 把权限错误和认证错误混成一类

## 先记住这三句

- SQLSTATE 帮你判断错误类型。
- 不是所有错误都能重试。
- 日志里保留错误码，排查会轻松很多。
