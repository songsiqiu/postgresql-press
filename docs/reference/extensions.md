# 扩展速查

扩展能给 PostgreSQL 增加能力。新手先知道扩展要评估、要授权、要考虑版本，不要在生产环境随手安装。

## 你学完能干什么

- 知道扩展解决什么问题
- 能区分“启用扩展”和“普通配置”
- 知道安装扩展前要检查什么
- 不会把扩展当成无成本功能开关

## 常见扩展方向

| 方向 | 可能用途 |
| --- | --- |
| 查询统计 | 观察 SQL 执行情况 |
| UUID | 生成 UUID |
| 加密 | 哈希、加密相关函数 |
| 外部数据 | 访问外部数据源 |
| 搜索和索引 | 增强搜索或索引能力 |

## 启用扩展示例

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

这类操作通常需要足够权限，而且可能需要先在配置中启用相关能力。

## 安装前检查

- 当前 PostgreSQL 版本是否支持
- 生产环境是否允许安装
- 权限是否足够
- 是否影响升级和备份恢复
- 应用是否真的需要

## 练习题

1. 扩展是普通表数据吗？
2. 生产库安装扩展前要不要评估？
3. `CREATE EXTENSION` 通常需要考虑什么权限？
4. 扩展会不会影响升级维护？

::: tip 提示
扩展是数据库能力的一部分，启用前要像改配置一样谨慎。
:::

::: details 答案
1. 不是，它会增加数据库能力或对象。
2. 要。
3. 需要有足够的数据库权限，具体取决于扩展。
4. 可能会，所以要评估版本和兼容性。
:::

## 常见坑

- 开发库装了扩展，生产库没有
- 不评估就安装不熟悉的扩展
- 忽略扩展对升级和恢复的影响

## 先记住这三句

- 扩展会改变数据库能力。
- 生产环境安装前要评估。
- 扩展也要纳入迁移和运维记录。
