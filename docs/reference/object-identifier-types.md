# 对象标识符类型速查

对象标识符类型主要用于 PostgreSQL 内部系统目录，常见代表是 `oid`。普通业务表通常不应该用它当业务主键。

## 你学完能干什么

- 知道 `oid` 更偏内部对象标识
- 能看懂系统目录里出现的 `oid`
- 不会把 `oid` 当普通业务 ID 滥用

## 可运行例子

查看当前库里部分表的对象标识：

```sql
SELECT oid, relname
FROM pg_class
WHERE relkind = 'r'
ORDER BY relname
LIMIT 5;
```

这里的 `oid` 是系统目录用来标识数据库对象的值。

## 常见类型

| 类型 | 说明 |
| --- | --- |
| `oid` | 对象标识符 |
| `regclass` | 表、索引、序列等关系对象的名称解析类型 |
| `regproc` | 函数名称解析类型 |
| `regtype` | 类型名称解析类型 |

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| `oid` | PostgreSQL 内部对象标识 |
| 业务主键 | 业务表自己设计的稳定标识 |
| `bigserial` | 常见自增整数主键写法 |
| `uuid` | 常见全局唯一标识 |

## 练习题

1. `oid` 更常见于业务表，还是系统目录？
2. 普通业务表主键应该默认用 `oid` 吗？
3. `regclass` 常用于解析哪类对象名？
4. 查看 `pg_class` 时看到 `oid` 是否正常？

::: tip 提示
看到 `oid`，先想到“数据库对象内部标识”，不要直接套到业务建模上。
:::

::: details 答案
1. 系统目录。
2. 不应该。
3. 表、索引、序列等关系对象名。
4. 正常。
:::

## 常见坑

- 把 `oid` 当业务 ID 使用
- 以为 `oid` 的含义跨库、跨环境稳定
- 查系统目录时不知道 `regclass` 这类类型能帮忙解析名称
- 把内部标识和业务标识混为一谈

## 先记住这三句

- `oid` 主要服务 PostgreSQL 内部对象标识。
- 业务主键不要默认用 `oid`。
- 查系统目录时再重点理解对象标识符类型。
