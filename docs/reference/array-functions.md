# 数组函数速查

数组函数用来处理一列里的多个值。数组很方便，但不能替代本该拆表的一对多关系。

## 你学完能干什么

- 能看懂常见数组函数
- 知道如何判断数组是否包含某个值
- 能把数组展开成多行
- 能避免用数组逃避关系建模

## 常见写法

```sql
SELECT array_length(ARRAY[10, 20, 30], 1);
```

结果是 `3`。

判断是否包含：

```sql
SELECT ARRAY['sql', 'index'] @> ARRAY['sql'];
```

结果是 `true`。

展开数组：

```sql
SELECT unnest(ARRAY['sql', 'index', 'transaction']);
```

会得到三行结果。

## 常见函数和操作符

| 写法 | 新手解释 |
| --- | --- |
| `array_length(arr, 1)` | 数组长度 |
| `unnest(arr)` | 把数组展开成多行 |
| `arr @> other` | 左边数组是否包含右边 |
| `arr && other` | 两个数组是否有交集 |

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 数组 | 一个字段里保存多个同类型值 |
| 维度 | 数组的层级 |
| 包含 | 一个数组是否覆盖另一个数组 |
| 展开 | 把数组元素变成多行 |

## 练习题

1. `array_length` 常用来查什么？
2. `unnest` 会把数组变成一行还是多行？
3. `@>` 常用来判断什么？
4. 数组适合替代所有一对多关系吗？

::: tip 提示
数组适合小范围、多值属性；复杂关系优先考虑拆表。
:::

::: details 答案
1. 数组长度。
2. 多行。
3. 包含关系。
4. 不适合。
:::

## 常见坑

- 用数组逃避本该拆表的关系
- 数组里塞不同含义的数据
- 不评估数组查询的索引需求
- 忘记空数组和 `NULL` 不是一回事

## 先记住这三句

- 数组保存多个同类型值。
- `unnest` 能把数组展开。
- 复杂关系不要硬塞数组。
