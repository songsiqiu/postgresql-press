# 位串类型速查

位串类型用来保存一串 0 和 1。它适合处理真正的位标志、掩码或协议字段，不适合替代清晰的业务列。

## 你学完能干什么

- 知道 `bit(n)` 和 `bit varying(n)` 的区别
- 能写出一个保存固定长度位标志的例子
- 知道普通业务布尔字段不必硬塞进位串

## 可运行例子

```sql
CREATE TABLE feature_masks (
  id bigserial PRIMARY KEY,
  flags bit(4) NOT NULL
);

INSERT INTO feature_masks (flags)
VALUES (B'1010');

SELECT flags, get_bit(flags::varbit, 0) AS first_bit
FROM feature_masks;
```

`B'1010'` 是位串字面量，表示四位二进制值。

## 常见类型

| 类型 | 说明 |
| --- | --- |
| `bit(n)` | 固定长度位串 |
| `bit varying(n)` | 可变长度位串 |
| `varbit(n)` | `bit varying(n)` 的简写 |

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| `boolean` | 一个真或假 |
| 位串 | 一串 0 和 1 |
| 掩码 | 用位表示多个开关或能力 |
| 文本 `1010` | 字符串，不具备位串运算语义 |

## 练习题

1. `bit(4)` 能保存 `B'1010'` 吗？
2. 一个普通“是否启用”字段应该优先用位串还是布尔类型？
3. `varbit` 是什么类型的简写？
4. 位串适合协议掩码这类场景吗？

::: tip 提示
如果每一位都有清晰含义，并且你确实要做位运算，再考虑位串。
:::

::: details 答案
1. 能。
2. 布尔类型。
3. `bit varying`。
4. 适合。
:::

## 常见坑

- 为了省字段，把多个业务状态压进一串位里
- 位的含义没有文档，后续无人敢改
- 把位串当字符串拼接和截取
- 普通开关字段不用 `boolean`，反而用位串增加理解成本

## 先记住这三句

- 位串保存的是一串二进制位。
- 普通真假字段用 `boolean` 就够了。
- 位串的每一位含义必须写清楚。
