# 配置参数速查

PostgreSQL 配置参数很多。新手先按用途分类查，不要直接背参数列表。

## 你学完能干什么

- 能按连接、内存、日志、维护、复制分类查参数
- 知道配置变更可能需要重载或重启
- 不会把参数调大当成万能优化

## 常见分类

| 分类 | 关注点 |
| --- | --- |
| 连接 | 监听地址、端口、最大连接数 |
| 内存 | 缓存、排序、工作内存 |
| 日志 | 日志级别、慢查询记录、日志位置 |
| 自动维护 | 清理旧版本、统计信息 |
| 复制 | WAL、归档、主从相关设置 |

## 改参数前的四个问题

1. 这个参数解决什么具体问题？
2. 影响当前会话、数据库，还是整个实例？
3. 改完是重载生效，还是必须重启？
4. 有回滚方案吗？

## 配置和性能的关系

有些性能问题确实和配置有关，但很多慢查询来自 SQL、索引、数据量、统计信息或锁等待。

不要看到慢就先改参数。

## 练习题

1. 日志相关参数主要帮助解决什么问题？
2. 改参数前为什么要确认是否需要重启？
3. 慢查询一定是配置参数不合理吗？
4. 最大连接数能无限调大吗？

::: tip 提示
参数是数据库行为的开关和边界，不是魔法加速器。
:::

::: details 答案
1. 记录错误、慢查询、连接和排障信息。
2. 重启会影响服务，需要安排窗口。
3. 不一定，也可能是 SQL、索引、锁、统计信息等问题。
4. 不能，连接会消耗数据库和机器资源。
:::

## 常见坑

- 照抄网上参数模板
- 慢查询不看执行计划，只改内存参数
- 改完不知道有没有生效
- 最大连接数调大却不看连接池

## 先记住这三句

- 参数要按问题分类查。
- 改配置前先确认生效方式。
- 性能问题不要只怪配置。
