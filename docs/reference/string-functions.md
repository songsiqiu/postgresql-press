# 字符串函数速查

字符串函数常用于清洗输入、展示文本和做简单匹配。复杂搜索不要只靠字符串函数硬撑，后面应考虑全文检索。

## 你学完能干什么

- 能找到常用大小写、截取、拼接函数
- 知道字符串匹配和全文检索不是一回事
- 能避免把格式化展示逻辑全部塞进 SQL

## 常用入口

| 写法 | 用途 |
| --- | --- |
| `lower(name)` | 转小写 |
| `upper(name)` | 转大写 |
| `length(name)` | 字符串长度 |
| `substring(name from 1 for 3)` | 截取字符串 |
| `trim(name)` | 去掉首尾空白 |
| `name || suffix` | 拼接字符串 |

## 常见例子

```sql
SELECT id, lower(email) AS normalized_email
FROM users
WHERE lower(email) = lower('Alice@Example.com');
```

这种写法能做不区分大小写的比较，但如果它是高频查询，要进一步考虑索引和表达式设计。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 拼接 | 把多个字符串连起来 |
| 截取 | 从字符串中取一段 |
| 规范化 | 把输入变成统一格式 |
| 全文检索 | 面向词、排名和搜索体验的能力 |

## 练习题

1. 把邮箱转小写可以用哪个函数？
2. 去掉首尾空白可以用哪个函数？
3. `||` 常用于做什么？
4. 复杂搜索应该只靠 `LIKE` 和字符串函数吗？

::: tip 提示
字符串函数适合轻量处理，搜索体验要看全文检索。
:::

::: details 答案
1. `lower`。
2. `trim`。
3. 字符串拼接。
4. 不应该。
:::

## 常见坑

- 在高频条件里随意套函数，导致索引无法直接使用
- 把大小写规范化只放在查询里，没有统一写入规则
- 用字符串函数承担复杂搜索系统的职责
- 在 SQL 里写过多展示层格式化逻辑

## 先记住这三句

- 字符串函数适合轻量清洗和展示。
- 高频查询要考虑索引影响。
- 复杂搜索要看全文检索。
