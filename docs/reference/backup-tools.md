# 备份工具速查

PostgreSQL 提供多种备份相关工具。新手先知道它们大概负责什么，不要把所有工具混成一类。

## 你学完能干什么

- 知道 `pg_dump`、`pg_restore`、`pg_basebackup` 大概用途
- 能区分逻辑备份和物理备份工具
- 知道恢复前要确认目标环境

## 常见工具

| 工具 | 大概用途 |
| --- | --- |
| `pg_dump` | 导出一个数据库的逻辑备份 |
| `pg_dumpall` | 导出整个集群里的全局对象和数据库 |
| `pg_restore` | 恢复特定格式的 `pg_dump` 备份 |
| `pg_basebackup` | 做物理基础备份，常用于复制和完整恢复 |
| `psql` | 执行 SQL 文件形式的导入 |

## 逻辑备份和物理备份

逻辑备份更像把对象定义和数据导出来。物理备份更像保存数据库文件层面的状态。

小型迁移、局部恢复常先看逻辑备份。完整实例恢复、复制搭建常会涉及物理备份。

## 恢复前确认

- 目标库是否正确
- 是否会覆盖已有数据
- 版本是否兼容
- 扩展是否安装
- 角色和权限是否存在

## 练习题

1. 导出一个数据库，常先想到哪个工具？
2. 恢复 `pg_dump` 特定格式备份，常用哪个工具？
3. `pg_basebackup` 更偏逻辑备份还是物理备份？
4. 恢复前为什么要确认目标库？

::: tip 提示
先判断你是要“导出对象和数据”，还是要“保存数据库文件层面的状态”。
:::

::: details 答案
1. `pg_dump`。
2. `pg_restore`。
3. 物理备份。
4. 防止覆盖错误环境或错误数据库。
:::

## 常见坑

- 备份文件没验证就以为安全
- 恢复到错误环境
- 忽略角色、权限、扩展这些非表数据

## 先记住这三句

- `pg_dump` 常用于逻辑备份。
- `pg_basebackup` 更偏物理基础备份。
- 恢复前先确认目标环境。
