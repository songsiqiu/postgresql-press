# SQL 关键字速查

SQL 关键字是 PostgreSQL 语法里有特殊含义的词。新手不需要背完整列表，但要知道命名时避开常见关键字。

## 你学完能干什么

- 知道为什么有些名字不能直接用
- 能理解保留关键字和普通标识符的区别
- 知道双引号能解决命名冲突但不推荐滥用
- 能给表名和列名起更稳的名字

## 一个例子

不建议这样给字段命名：

```sql
CREATE TABLE demo_orders (
  id bigserial PRIMARY KEY,
  user text,
  order text
);
```

`user`、`order` 这类词容易和 SQL 语法或常见含义冲突。更清楚的写法是：

```sql
CREATE TABLE demo_orders (
  id bigserial PRIMARY KEY,
  user_name text,
  order_note text
);
```

## 双引号不是首选

```sql
SELECT "order"
FROM demo_orders;
```

双引号可以让特殊名字可用，但以后每次引用都要严格写对大小写和引号，维护成本会变高。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 关键字 | SQL 里有特殊含义的词 |
| 保留关键字 | 更不适合直接当对象名的词 |
| 标识符 | 表名、列名、函数名这类名字 |
| 双引号标识符 | 用双引号强制保留原样的名字 |

## 练习题

1. 表名列名应该尽量避开关键字吗？
2. 双引号能不能让特殊列名可用？
3. 双引号命名适合日常大量使用吗？
4. `order_note` 比 `order` 更适合做列名吗？

::: tip 提示
命名先追求清楚和稳定，不要靠双引号硬扛关键字冲突。
:::

::: details 答案
1. 应该。
2. 能。
3. 不适合。
4. 更适合，含义更清楚，也更不容易冲突。
:::

## 常见坑

- 用关键字当列名，后续 SQL 到处加引号
- 双引号导致大小写必须完全匹配
- 表名太短，看不出业务含义
- 为了省几个字符牺牲可读性

## 先记住这三句

- 命名尽量避开关键字。
- 双引号能救急，但会增加维护成本。
- 好名字比短名字更重要。
