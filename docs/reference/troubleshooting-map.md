# 排查入口速查

遇到数据库问题时，先判断问题属于哪一类，再进入对应章节。不要所有问题都从“数据库慢了”开始猜。

## 你学完能干什么

- 能把常见问题归类
- 知道每类问题先看哪几页
- 能更清楚地向别人描述问题
- 避免一上来就乱改配置或 SQL

## 常见问题入口

| 现象 | 先看哪里 |
| --- | --- |
| 连不上数据库 | 连接方式、认证与访问规则、配置参数 |
| 能连但没权限 | 权限与安全、错误码速查 |
| SQL 慢 | EXPLAIN 读法、索引基础、规划器与代价 |
| 更新卡住 | 锁与等待、事务隔离级别 |
| 数据误删 | 备份与恢复、备份工具速查 |
| 从库数据旧 | 复制与高可用、监控与容量 |
| 批量导入失败 | COPY 与批量导入、数据类型、约束与关系 |

## 描述问题的模板

排查时尽量说清楚：

- 页面或接口入口
- 发生时间
- 数据库用户和数据库名
- SQL 或业务动作
- 错误码或原始错误
- 是否能稳定复现

## 练习题

1. SQL 慢时，先看哪两个方向？
2. 更新一直不结束，可能先看哪一页？
3. 批量导入失败，除了文件格式还要看什么？
4. 向别人求助时为什么要保留原始错误？

::: tip 提示
排查的第一步不是修改，而是分类。
:::

::: details 答案
1. EXPLAIN 读法、索引基础，也可以看规划器与代价。
2. 锁与等待。
3. 目标表结构、数据类型、约束、编码等。
4. 原始错误能帮助定位具体类型和来源。
:::

## 常见坑

- 只说“数据库不行了”，没有现象和时间
- 慢查询不看执行计划
- 权限问题和认证问题混着说

## 先记住这三句

- 排查先分类。
- 慢查询先看执行计划。
- 错误信息要完整保留。
