# UUID 速查

UUID 常用于生成不容易冲突的标识。它适合分布式生成、外部暴露 ID 等场景，但不等于所有主键都必须用 UUID。

## 你学完能干什么

- 知道 UUID 适合什么场景
- 能理解 UUID 和自增 ID 的差异
- 知道生成 UUID 需要相应函数或扩展能力
- 能避免把 UUID 当成连续业务编号

## 类型和例子

```sql
CREATE TABLE public_events (
  id uuid PRIMARY KEY,
  title text NOT NULL
);
```

插入时可以使用应用生成的 UUID，也可以使用数据库函数生成，具体取决于项目约定和已启用能力。

## UUID 和自增 ID

| 选择 | 特点 |
| --- | --- |
| 自增 ID | 简短、递增、适合内部主键 |
| UUID | 分散生成、不容易猜测、较长 |

UUID 不保证按创建时间连续，也不适合直接拿来当业务流水号。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| UUID | 通用唯一标识符 |
| 主键 | 唯一标识一行 |
| 业务编号 | 给人看的业务序号 |
| 随机性 | 不按简单递增规律出现 |

## 练习题

1. UUID 适合做连续业务编号吗？
2. UUID 比自增 ID 更短吗？
3. 分布式生成 ID 时，UUID 有没有优势？
4. UUID 可以作为主键类型吗？

::: tip 提示
先分清“数据库内部标识”和“给人看的业务编号”。
:::

::: details 答案
1. 不适合。
2. 不是，通常更长。
3. 有。
4. 可以。
:::

## 常见坑

- 把 UUID 当成连续编号
- 所有表都无脑使用 UUID
- 没考虑索引体积和展示成本
- 数据库和应用两边生成规则不统一

## 先记住这三句

- UUID 适合不易冲突的标识。
- UUID 不是业务流水号。
- 是否用 UUID 要看场景。
