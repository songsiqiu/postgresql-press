# 约束命令速查

约束命令用来让数据库直接保护数据规则。新手先掌握主键、唯一、非空、检查和外键。

## 你学完能干什么

- 能查到常见约束的创建方式
- 知道约束和应用校验不是一回事
- 能理解约束报错是在保护数据
- 能避免只靠前端或后端代码保证数据正确

## 常见约束

```sql
CREATE TABLE users (
  id bigserial PRIMARY KEY,
  email text NOT NULL UNIQUE,
  age integer CHECK (age >= 0)
);
```

外键例子：

```sql
CREATE TABLE orders (
  id bigserial PRIMARY KEY,
  user_id bigint NOT NULL REFERENCES users(id)
);
```

## 后加约束

```sql
ALTER TABLE users
ADD CONSTRAINT users_email_unique UNIQUE (email);
```

给已有表加约束前，要先确认历史数据是否满足规则。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 主键 | 唯一标识一行 |
| 唯一约束 | 保证某列或某组列不重复 |
| 非空约束 | 不允许值为 `NULL` |
| 检查约束 | 要求值满足表达式 |
| 外键 | 保证引用关系存在 |

## 练习题

1. 保证邮箱不重复，可以用哪类约束？
2. 保证年龄不能小于 0，可以用哪类约束？
3. 外键主要保护什么关系？
4. 给已有表加约束前，为什么要检查历史数据？

::: tip 提示
约束是数据库层面的底线，应用校验不能完全替代它。
:::

::: details 答案
1. 唯一约束。
2. 检查约束。
3. 表之间的引用关系。
4. 如果历史数据违反规则，添加约束会失败。
:::

## 常见坑

- 只在应用里校验，不在数据库加约束
- 给已有表加约束前不查脏数据
- 外键关系和业务删除规则没想清楚
- 约束命名太随意，排错时看不懂

## 先记住这三句

- 约束让数据库保护数据规则。
- 应用校验不能完全替代约束。
- 给已有数据加约束前先查历史数据。
