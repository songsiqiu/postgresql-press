# 角色权限速查

角色和权限决定谁能连接数据库、谁能操作对象。新手先把“身份”和“能力”分开看。

## 你学完能干什么

- 能区分角色、登录、权限
- 知道 `GRANT` 和 `REVOKE` 大概做什么
- 能理解为什么业务账号不该是超级用户
- 能按问题判断是认证还是授权

## 常见语句

```sql
CREATE ROLE app_user LOGIN PASSWORD 'change_me';
GRANT SELECT, INSERT ON notes TO app_user;
REVOKE INSERT ON notes FROM app_user;
```

## 常见权限

| 权限 | 能做什么 |
| --- | --- |
| `SELECT` | 查询 |
| `INSERT` | 插入 |
| `UPDATE` | 更新 |
| `DELETE` | 删除 |
| `USAGE` | 使用模式、序列等对象 |
| `CREATE` | 创建对象 |

## 认证和授权

| 问题 | 说明 |
| --- | --- |
| 认证 | 能不能连进来 |
| 授权 | 连进来后能不能操作对象 |

能连上但不能查表，通常更像授权问题。

## 练习题

1. `GRANT SELECT ON notes TO app_user;` 做了什么？
2. `REVOKE` 是授权还是撤销权限？
3. 能连上但不能查表，更像认证问题还是授权问题？
4. 为什么业务账号不该用超级用户？

::: tip 提示
先问“这个角色是谁”，再问“它应该能做什么”。
:::

::: details 答案
1. 给 `app_user` 查询 `notes` 表的权限。
2. 撤销权限。
3. 授权问题。
4. 权限过大，出错或泄露时影响范围太大。
:::

## 常见坑

- 所有应用共用一个数据库账号
- 为了省事给超级用户
- 只授表权限，忘记模式或序列权限

## 先记住这三句

- 角色是身份，权限是能力。
- 能连上不代表能操作对象。
- 业务账号权限够用就好。
