# ALTER DEFAULT PRIVILEGES 速查

`ALTER DEFAULT PRIVILEGES` 用来设置未来新建对象的默认权限。它不会自动修改已经存在的表、序列或函数。

## 你学完能干什么

- 知道默认权限只影响未来对象
- 能看懂给未来表授权的基本写法
- 能区分默认权限和已有对象授权
- 能避免新表创建后权限缺失

## 给未来表设置默认权限

```sql
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT ON TABLES TO app_readonly;
```

这表示以后在 `public` 模式中新建的表，默认给 `app_readonly` 查询权限。

已有表仍然需要单独授权：

```sql
GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_readonly;
```

## 适合场景

- 应用经常新建表
- 希望只读角色自动获得未来表权限
- 避免每次建表后手动补授权
- 多团队协作时统一权限口径

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 默认权限 | 对未来新对象生效的授权规则 |
| 已有对象权限 | 当前已经存在对象上的权限 |
| 模式范围 | 默认权限在哪个模式内生效 |
| 授权者 | 谁创建对象，默认权限就按谁的规则生效 |

## 练习题

1. 默认权限会自动修改已有表权限吗？
2. 想给已有表授权应该用 `GRANT` 还是默认权限？
3. 默认权限可以限制在某个模式里吗？
4. 为什么新表经常出现“读不了”的问题？

::: tip 提示
默认权限管未来，`GRANT` 管当前已有对象。
:::

::: details 答案
1. 不会。
2. `GRANT`。
3. 可以。
4. 可能只给了已有表权限，没有设置未来新表的默认权限。
:::

## 常见坑

- 以为默认权限会补齐已有表
- 没指定模式范围，结果和预期不一致
- 忘记序列和函数也可能需要默认权限
- 不知道默认权限和对象创建者有关

## 先记住这三句

- 默认权限只管未来对象。
- 已有对象仍要单独授权。
- 默认权限要结合模式和创建者理解。
