# CREATE VIEW 与 DROP VIEW 速查

`CREATE VIEW` 用来创建视图，`DROP VIEW` 用来删除视图。普通视图保存的是查询定义，不是复制出来的一张表。

## 你学完能干什么

- 能看懂创建视图的基本语法
- 知道普通视图保存的是查询定义
- 能理解视图适合复用查询
- 能避免把视图当成实时物化结果

## 创建视图

```sql
CREATE VIEW active_notes AS
SELECT id, title, created_at
FROM notes
WHERE archived = false;
```

之后可以像查表一样查询它：

```sql
SELECT *
FROM active_notes
ORDER BY created_at DESC;
```

删除视图：

```sql
DROP VIEW active_notes;
```

## 适合什么时候用

- 常用查询需要一个清楚名字
- 多个地方复用同一段查询
- 想隐藏一部分复杂表结构
- 想让读者先看更简单的结果

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 普通视图 | 保存查询定义 |
| 物化视图 | 保存查询结果，需要刷新 |
| 依赖 | 视图引用了哪些表或对象 |
| 查询复用 | 给常用查询起名字 |

## 练习题

1. 普通视图保存的是数据副本还是查询定义？
2. 创建视图用什么命令？
3. 删除视图会删除底层表吗？
4. 视图适合给复杂查询起名字吗？

::: tip 提示
先把普通视图理解成“有名字的查询”。
:::

::: details 答案
1. 查询定义。
2. `CREATE VIEW`。
3. 不会。
4. 适合。
:::

## 常见坑

- 把普通视图当成复制出来的表
- 底层表结构变了却忘记检查视图
- 用视图隐藏过多复杂业务逻辑
- 删除视图前不看依赖它的查询

## 先记住这三句

- 普通视图保存查询定义。
- 视图适合复用查询。
- 删除视图不等于删除底层表。
