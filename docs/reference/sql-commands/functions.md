# CREATE FUNCTION 与 DROP FUNCTION 速查

`CREATE FUNCTION` 用来创建数据库函数，`DROP FUNCTION` 用来删除函数。函数适合封装靠近数据的明确逻辑。

## 你学完能干什么

- 能看懂创建函数的基本结构
- 知道函数适合复用数据库内逻辑
- 能理解删除函数前要确认调用方
- 能避免把复杂业务全部塞进函数

## 创建函数

```sql
CREATE FUNCTION add_one(x integer)
RETURNS integer
LANGUAGE sql
AS $$
  SELECT x + 1;
$$;
```

调用它：

```sql
SELECT add_one(10);
```

删除函数时通常需要写参数类型：

```sql
DROP FUNCTION add_one(integer);
```

## 适合什么时候用

- 多处 SQL 复用同一段计算
- 逻辑非常靠近数据
- 希望在数据库里统一一个小规则
- 不适合隐藏整套复杂业务流程

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 函数 | 输入参数后返回结果的数据库对象 |
| 返回类型 | 函数结果是什么类型 |
| 参数类型 | 函数接收什么类型的输入 |
| 过程语言 | 编写函数使用的语言 |

## 练习题

1. `CREATE FUNCTION` 用来创建什么对象？
2. 删除重名函数时为什么常常要写参数类型？
3. 函数适合隐藏整套复杂业务吗？
4. `RETURNS integer` 表示什么？

::: tip 提示
函数适合小而明确的复用逻辑，不适合把应用业务全部藏进数据库。
:::

::: details 答案
1. 数据库函数。
2. PostgreSQL 允许同名不同参数的函数，参数类型能定位具体函数。
3. 不适合。
4. 函数返回整数。
:::

## 常见坑

- 函数里藏太多业务逻辑
- 删除函数前不查谁在调用
- 忽略函数权限和执行身份
- 修改函数后没有同步测试调用方

## 先记住这三句

- 函数封装靠近数据的小逻辑。
- 删除函数要确认参数和依赖。
- 不要把复杂业务全藏进函数。
