# CREATE TABLESPACE 与 DROP TABLESPACE 速查

表空间用来指定数据库对象存放在哪个文件系统位置。它是存储管理工具，不是备份方案。

## 你学完能干什么

- 知道表空间控制存储位置
- 能看懂创建表空间的基本语法
- 知道删除表空间前要确认里面没有对象
- 能避免把表空间当成备份

## 创建表空间

```sql
CREATE TABLESPACE fast_space
LOCATION '/data/pg_fast';
```

创建表时指定表空间：

```sql
CREATE TABLE notes_archive (
  id bigserial PRIMARY KEY,
  title text NOT NULL
) TABLESPACE fast_space;
```

删除表空间：

```sql
DROP TABLESPACE fast_space;
```

删除前要确认表空间里没有对象，并确认底层目录管理符合运维规范。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 表空间 | 控制对象存储位置 |
| 数据目录 | PostgreSQL 默认保存数据的位置 |
| 存储迁移 | 把对象移动到其他存储位置 |
| 备份 | 用于恢复的数据副本 |

## 练习题

1. 表空间主要控制什么？
2. 表空间是备份方案吗？
3. 删除表空间前要确认里面有没有对象吗？
4. 创建表时能指定表空间吗？

::: tip 提示
表空间解决“放哪里”，备份解决“坏了怎么恢复”。
:::

::: details 答案
1. 数据库对象的存储位置。
2. 不是。
3. 要。
4. 能。
:::

## 常见坑

- 把表空间当成备份
- 不了解底层目录权限就创建表空间
- 删除表空间前不查对象
- 用表空间掩盖容量规划问题

## 先记住这三句

- 表空间控制存储位置。
- 表空间不是备份。
- 删除表空间前先确认对象和目录。
