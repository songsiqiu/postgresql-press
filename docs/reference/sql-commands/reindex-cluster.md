# REINDEX 与 CLUSTER 速查

`REINDEX` 用来重建索引，`CLUSTER` 用来按索引顺序重排表数据。它们属于维护命令，执行前要评估影响。

## 你学完能干什么

- 知道什么时候可能考虑重建索引
- 能理解 `CLUSTER` 会重排表数据
- 知道维护命令可能加锁和耗时
- 能避免把维护命令当成日常随手操作

## 重建索引

```sql
REINDEX INDEX idx_notes_user_id;
```

也可以对表重建索引：

```sql
REINDEX TABLE notes;
```

## 按索引重排表

```sql
CLUSTER notes USING idx_notes_user_id;
```

这会按指定索引顺序重排表数据，适合非常明确的访问模式，但不是万能优化。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `REINDEX` | 重建索引 |
| `CLUSTER` | 按索引顺序重排表 |
| 索引膨胀 | 索引占用变大但有效数据不多 |
| 维护窗口 | 允许执行影响较大操作的时间段 |

## 练习题

1. `REINDEX` 是重建表还是重建索引？
2. `CLUSTER` 会不会重排表数据？
3. 这类维护命令上线前要不要评估锁和耗时？
4. `CLUSTER` 是不是所有慢查询的通用解法？

::: tip 提示
维护命令先在测试环境评估，再决定是否放到维护窗口执行。
:::

::: details 答案
1. 重建索引。
2. 会。
3. 要。
4. 不是。
:::

## 常见坑

- 生产高峰期执行重维护命令
- 没确认索引膨胀就随手重建
- 把 `CLUSTER` 当成通用性能按钮
- 不评估锁影响和磁盘空间

## 先记住这三句

- `REINDEX` 重建索引。
- `CLUSTER` 重排表数据。
- 维护命令要先评估影响。
