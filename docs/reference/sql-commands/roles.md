# CREATE ROLE 与 DROP ROLE 速查

`CREATE ROLE` 用来创建角色，`DROP ROLE` 用来删除角色。PostgreSQL 里的用户和权限身份都由角色承载。

## 你学完能干什么

- 能理解角色是权限身份
- 知道登录账号也是角色的一种用法
- 能看懂创建应用角色的基本语法
- 能避免直接用超级用户跑应用

## 创建角色

```sql
CREATE ROLE app_user LOGIN PASSWORD 'change_me';
```

这会创建一个可以登录的角色。实际生产中，密码要由安全流程管理，不要写进公开脚本。

创建权限组角色：

```sql
CREATE ROLE app_readonly;
```

删除角色：

```sql
DROP ROLE old_user;
```

删除前要先确认它是否拥有对象或仍被授权。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 角色 | 权限身份 |
| 登录角色 | 可以连接数据库的角色 |
| 组角色 | 用来承载一组权限的角色 |
| 超级用户 | 拥有极高权限的角色 |

## 练习题

1. PostgreSQL 里的用户和权限身份主要由什么承载？
2. `LOGIN` 表示这个角色能不能登录？
3. 应用适合使用超级用户连接数据库吗？
4. 删除角色前为什么要检查它是否拥有对象？

::: tip 提示
先把角色理解成“权限身份”，再区分它能不能登录。
:::

::: details 答案
1. 角色。
2. 表示能登录。
3. 不适合。
4. 角色拥有对象时，直接删除可能失败或影响对象管理。
:::

## 常见坑

- 把角色只理解成登录用户
- 应用账号使用超级用户
- 不用组角色管理权限
- 删除角色前不检查对象归属

## 先记住这三句

- 角色承载权限身份。
- 能登录的角色才像普通账号。
- 应用账号要最小权限。
