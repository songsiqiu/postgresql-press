# LOCK 速查

`LOCK` 用来显式锁定表。它是比较强的并发控制手段，新手应先理解风险，再考虑使用。

## 你学完能干什么

- 知道 `LOCK` 会影响并发访问
- 能看懂锁表的基本写法
- 知道大多数业务优先考虑行锁或事务设计
- 能避免长时间持有表锁

## 锁表写法

```sql
BEGIN;

LOCK TABLE notes IN SHARE MODE;

-- 执行需要保护的操作

COMMIT;
```

锁通常要放在事务里理解，事务结束时释放。

## 什么时候谨慎使用

- 数据迁移期间需要保护结构或数据
- 管理脚本需要短时间阻止并发修改
- 排查并发问题时需要明确控制
- 不适合日常业务里随手锁整张表

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 表锁 | 锁住表级别访问 |
| 行锁 | 锁住具体数据行 |
| 锁模式 | 不同强度的锁 |
| 等待 | 其他事务可能被阻塞 |

## 练习题

1. `LOCK TABLE` 通常影响整张表还是某一行？
2. 锁表后事务长期不提交会怎样？
3. 日常更新一行数据优先考虑表锁还是行锁？
4. 锁通常什么时候释放？

::: tip 提示
锁越大，影响越大；能锁行就不要轻易锁整表。
:::

::: details 答案
1. 整张表。
2. 其他事务可能长期等待。
3. 优先考虑行锁或正常事务设计。
4. 通常事务结束时释放。
:::

## 常见坑

- 业务代码里随手锁整张表
- 锁表后执行慢操作
- 不知道锁模式差异就复制命令
- 没监控等待就上线管理脚本

## 先记住这三句

- `LOCK` 是强并发控制手段。
- 表锁影响范围比行锁大。
- 锁住后要尽快提交或回滚。
