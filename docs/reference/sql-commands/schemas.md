# CREATE SCHEMA 与 DROP SCHEMA 速查

`CREATE SCHEMA` 用来创建模式，`DROP SCHEMA` 用来删除模式。模式可以理解成数据库里的分类目录。

## 你学完能干什么

- 能理解模式的用途
- 能创建一个新的模式
- 知道删除模式前要确认里面有什么对象
- 能避免把模式和数据库混成一回事

## 创建模式

```sql
CREATE SCHEMA app;
```

创建表时可以放到这个模式里：

```sql
CREATE TABLE app.notes (
  id bigserial PRIMARY KEY,
  title text NOT NULL
);
```

删除空模式：

```sql
DROP SCHEMA app;
```

如果模式里还有对象，删除会失败，除非明确处理依赖。

## 什么时候用模式

- 按业务模块组织表
- 区分扩展对象和业务对象
- 给不同团队或功能划分命名空间
- 避免所有表都堆在 `public`

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 数据库 | 独立的数据空间 |
| 模式 | 数据库里的分类目录 |
| 命名空间 | 避免对象名字冲突的范围 |
| `public` | 默认常见模式 |

## 练习题

1. 模式在数据库里面，还是数据库在模式里面？
2. 创建模式用什么命令？
3. 删除有对象的模式前要不要确认依赖？
4. `app.notes` 里的 `app` 是表名还是模式名？

::: tip 提示
按“数据库 > 模式 > 表”的层级理解最稳。
:::

::: details 答案
1. 模式在数据库里面。
2. `CREATE SCHEMA`。
3. 要。
4. 模式名。
:::

## 常见坑

- 把模式当成数据库
- 所有对象都放在 `public`，后续难整理
- 删除模式前不看里面有哪些对象
- 引用对象时忘记模式名

## 先记住这三句

- 模式是数据库里的目录。
- 模式能帮助组织对象。
- 删除模式前先看里面有什么。
