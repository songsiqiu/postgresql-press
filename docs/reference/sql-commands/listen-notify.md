# LISTEN、NOTIFY、UNLISTEN 速查

`LISTEN`、`NOTIFY`、`UNLISTEN` 是 PostgreSQL 的轻量通知机制。它适合简单事件提醒，不适合替代可靠消息队列。

## 你学完能干什么

- 知道 `LISTEN` 和 `NOTIFY` 的关系
- 能理解通知是轻量提醒
- 知道取消监听用什么命令
- 能避免把它当成可靠消息队列

## 监听和通知

一个会话监听频道：

```sql
LISTEN notes_changed;
```

另一个会话发送通知：

```sql
NOTIFY notes_changed, 'note updated';
```

取消监听：

```sql
UNLISTEN notes_changed;
```

## 适合场景

- 通知应用“某类数据变了”
- 轻量刷新缓存
- 开发简单内部提醒
- 不适合承载必须送达的业务消息

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `LISTEN` | 监听频道 |
| `NOTIFY` | 向频道发送通知 |
| `UNLISTEN` | 取消监听 |
| 可靠消息队列 | 有确认、重试、持久化等保证的消息系统 |

## 练习题

1. `LISTEN` 是发送通知还是监听通知？
2. `NOTIFY` 可以带一段简单文本吗？
3. 取消监听用什么命令？
4. `NOTIFY` 适合替代可靠消息队列吗？

::: tip 提示
把它当成“轻量提醒”，不要当成“必须送达的消息系统”。
:::

::: details 答案
1. 监听通知。
2. 可以。
3. `UNLISTEN`。
4. 不适合。
:::

## 常见坑

- 把通知当成可靠消息队列
- 监听连接断开后没有重连处理
- 通知内容塞太多业务数据
- 不清理不再需要的监听

## 先记住这三句

- `LISTEN` 监听，`NOTIFY` 通知。
- 它适合轻量提醒。
- 重要业务消息要用可靠消息系统。
