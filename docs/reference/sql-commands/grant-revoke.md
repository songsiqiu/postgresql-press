# GRANT 与 REVOKE 速查

`GRANT` 用来授权，`REVOKE` 用来撤销权限。它们是数据库权限管理的基础命令。

## 你学完能干什么

- 能看懂给角色授权的基本语法
- 知道撤销权限用什么命令
- 能区分对象权限和角色身份
- 能避免直接把超级用户给应用

## 授权示例

```sql
GRANT SELECT, INSERT
ON TABLE notes
TO app_user;
```

这表示允许 `app_user` 查询和插入 `notes` 表。

撤销权限：

```sql
REVOKE INSERT
ON TABLE notes
FROM app_user;
```

## 常见授权对象

- 表
- 模式
- 序列
- 函数
- 数据库

授权前要先想清楚角色需要做什么，不要一次给过大权限。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `GRANT` | 增加权限 |
| `REVOKE` | 撤销权限 |
| 角色 | 承载登录身份或权限集合 |
| 对象权限 | 对表、模式、序列等对象能做什么 |

## 练习题

1. 给角色增加权限用 `GRANT` 还是 `REVOKE`？
2. 撤销表插入权限应该用哪个命令？
3. 应用连接数据库适合直接用超级用户吗？
4. 表权限和角色身份是一回事吗？

::: tip 提示
先按角色实际需要授权，不要为了省事给最大权限。
:::

::: details 答案
1. `GRANT`。
2. `REVOKE INSERT ON TABLE ... FROM ...`。
3. 不适合。
4. 不是。角色是身份或权限集合，对象权限是这个角色能对对象做什么。
:::

## 常见坑

- 应用直接使用超级用户
- 授权给个人账号，不通过角色组管理
- 只给了表权限，忘记序列权限
- 撤销权限前不确认依赖关系

## 先记住这三句

- `GRANT` 加权限，`REVOKE` 收权限。
- 权限要按角色职责给。
- 应用账号不要用超级用户。
