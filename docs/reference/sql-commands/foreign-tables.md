# FOREIGN TABLE 速查

外部表让 PostgreSQL 通过外部数据封装器访问外部数据。它看起来像表，但数据通常不在当前数据库里。

## 你学完能干什么

- 知道外部表用于访问外部数据
- 能理解外部服务器和用户映射的作用
- 知道外部表不等于本地普通表
- 能避免把外部查询成本当成本地查询成本

## 基本结构

外部表通常需要先有扩展和外部服务器，再创建外部表。

```sql
CREATE FOREIGN TABLE remote_notes (
  id bigint,
  title text
)
SERVER remote_server
OPTIONS (schema_name 'public', table_name 'notes');
```

具体可用选项取决于使用的外部数据封装器。

## 相关对象

| 对象 | 新手解释 |
| --- | --- |
| 外部数据封装器 | 连接外部数据源的能力 |
| 外部服务器 | 外部数据源的连接定义 |
| 用户映射 | 当前角色访问外部源的凭据映射 |
| 外部表 | 当前库里映射外部数据的表定义 |

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 本地表 | 数据存放在当前库 |
| 外部表 | 数据通常在外部系统 |
| 下推 | 把过滤等操作交给外部系统执行 |
| 远程成本 | 外部连接、网络和远程执行带来的成本 |

## 练习题

1. 外部表的数据一定存放在当前数据库里吗？
2. 外部表访问成本一定和本地表一样吗？
3. 用户映射和访问凭据有没有关系？
4. 外部表适合不评估就放进核心高频查询吗？

::: tip 提示
看到外部表，先想“数据在哪里、谁来执行、网络成本多少”。
:::

::: details 答案
1. 不一定，通常在外部系统。
2. 不一定。
3. 有关系。
4. 不适合。
:::

## 常见坑

- 把外部表当成本地表一样使用
- 不评估网络和远程查询成本
- 凭据配置不清楚，权限排查困难
- 外部系统变慢时误以为本地数据库慢

## 先记住这三句

- 外部表映射外部数据。
- 外部查询有远程成本。
- 外部表要结合封装器和权限一起看。
