# BEGIN、COMMIT、ROLLBACK 速查

`BEGIN`、`COMMIT`、`ROLLBACK` 用来控制事务。它们决定一组修改是一起生效，还是一起撤回。

## 你学完能干什么

- 能看懂事务的最小写法
- 知道提交和回滚的区别
- 能用事务保护多步修改
- 能避免事务开太久

## 最小写法

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

UPDATE accounts
SET balance = balance + 100
WHERE id = 2;

COMMIT;
```

这两条更新会一起提交。如果中途发现问题，可以执行：

```sql
ROLLBACK;
```

## 什么时候用事务

- 一个业务动作需要改多行或多张表
- 中间任何一步失败都应该全部撤回
- 需要让一组操作保持一致
- 批量修改前希望有明确边界

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `BEGIN` | 开始事务 |
| `COMMIT` | 提交事务，让修改生效 |
| `ROLLBACK` | 回滚事务，撤回未提交修改 |
| 长事务 | 长时间不提交或回滚的事务 |

## 练习题

1. `COMMIT` 是确认修改还是撤回修改？
2. `ROLLBACK` 会撤回已经提交的事务吗？
3. 多步转账为什么适合放进事务？
4. 事务开了很久不提交有什么风险？

::: tip 提示
事务像一个明确边界：边界里的操作要么一起成功，要么一起撤回。
:::

::: details 答案
1. 确认修改。
2. 不会，它撤回未提交的修改。
3. 两边账户变动必须保持一致。
4. 可能长期占用锁和旧版本，影响其他操作。
:::

## 常见坑

- 开了事务后忘记提交或回滚
- 在事务里等待人工操作或远程接口
- 以为 `ROLLBACK` 能撤回已经 `COMMIT` 的内容
- 批量修改没有事务边界

## 先记住这三句

- `BEGIN` 开始，`COMMIT` 生效，`ROLLBACK` 撤回。
- 多步修改要有事务边界。
- 事务不要开太久。
