# CREATE EXTENSION 与 DROP EXTENSION 速查

`CREATE EXTENSION` 用来安装扩展，`DROP EXTENSION` 用来移除扩展。扩展可以给 PostgreSQL 增加新能力。

## 你学完能干什么

- 知道扩展是能力增强组件
- 能看懂安装扩展的基本语法
- 知道扩展会影响升级和运维
- 能避免不评估就安装扩展

## 安装扩展

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

这会安装 `pg_stat_statements` 扩展，用来统计 SQL 执行情况。

移除扩展：

```sql
DROP EXTENSION pg_stat_statements;
```

删除扩展前要确认有没有对象或功能依赖它。

## 安装前先问

- 这个扩展解决什么问题？
- 生产环境是否允许安装？
- 升级时是否有兼容风险？
- 应用或监控是否依赖它？

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 扩展 | 给 PostgreSQL 增加能力的组件 |
| 安装扩展 | 在数据库里启用扩展对象 |
| 依赖 | 其他对象或功能需要这个扩展 |
| 兼容性 | 升级或迁移时是否能正常工作 |

## 练习题

1. 安装扩展用什么命令？
2. 扩展是普通表数据吗？
3. 删除扩展前为什么要确认依赖？
4. `IF NOT EXISTS` 能减少重复安装报错吗？

::: tip 提示
扩展不是装饰品，安装前先确认用途、权限和后续维护。
:::

::: details 答案
1. `CREATE EXTENSION`。
2. 不是，它是能力组件。
3. 避免影响依赖这个扩展的对象或功能。
4. 能。
:::

## 常见坑

- 不评估就在生产库安装扩展
- 忽略扩展版本和升级兼容性
- 删除扩展前不查依赖
- 把扩展能力当成默认内置能力

## 先记住这三句

- 扩展会增加数据库能力。
- 安装前先确认用途和权限。
- 删除扩展前先看依赖。
