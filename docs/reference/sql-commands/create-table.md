# CREATE TABLE 速查

`CREATE TABLE` 用来创建表结构。它决定数据以后怎么存、哪些数据能不能进来。

## 你学完能干什么

- 能看懂建表语句的基本结构
- 知道主键、非空和唯一约束放在哪里
- 能选择常见字段类型
- 能避免建表时只堆字段不设约束

## 最小写法

```sql
CREATE TABLE demo_users (
  id bigserial PRIMARY KEY,
  name text NOT NULL,
  email text UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

这张表有自增主键、必填名称、唯一邮箱和创建时间。

## 建表前先问

- 每一行表示什么？
- 哪些字段不能为空？
- 哪些字段不能重复？
- 哪些字段适合由数据库给默认值？

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 字段类型 | 一列能保存什么样的值 |
| 主键 | 每一行的唯一身份 |
| 默认值 | 没传值时数据库自动填入 |
| 约束 | 数据进入表前要满足的规则 |

## 练习题

1. `PRIMARY KEY` 通常用来标识什么？
2. `NOT NULL` 解决什么问题？
3. `DEFAULT now()` 常用于什么字段？
4. 为什么建表时要先想清楚每一行表示什么？

::: tip 提示
建表不是把字段列完，而是把数据规则一起定下来。
:::

::: details 答案
1. 每一行的唯一身份。
2. 防止关键字段为空。
3. 创建时间这类默认当前时间的字段。
4. 这样才能判断字段和约束是否合理。
:::

## 常见坑

- 只有字段，没有约束
- 所有字段都用 `text`
- 用业务含义不清楚的列名
- 先上线再补主键和唯一约束

## 先记住这三句

- 表结构就是数据规则。
- 主键、非空、唯一要尽早想清楚。
- 好表名和好列名会降低后续维护成本。
