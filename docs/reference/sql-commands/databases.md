# CREATE DATABASE 与 DROP DATABASE 速查

`CREATE DATABASE` 用来创建数据库，`DROP DATABASE` 用来删除数据库。数据库是 PostgreSQL 实例里的独立数据空间。

## 你学完能干什么

- 能创建一个新数据库
- 能区分数据库、模式和表
- 知道删除数据库影响很大
- 能避免连错环境后误删

## 创建数据库

```sql
CREATE DATABASE app_demo;
```

连接到这个数据库后，才能在里面创建模式、表和其他对象。

删除数据库：

```sql
DROP DATABASE old_demo;
```

删除数据库会删除其中的对象和数据。执行前必须确认环境、连接目标和备份。

## 层级关系

| 层级 | 新手理解 |
| --- | --- |
| 实例 | 正在运行的 PostgreSQL 服务 |
| 数据库 | 实例里的独立数据空间 |
| 模式 | 数据库里的分类目录 |
| 表 | 存放具体数据的结构 |

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 数据库 | 独立数据空间 |
| 模式 | 数据库里的目录 |
| 连接目标 | 当前客户端连到哪个数据库 |
| 备份 | 删除前用于恢复的数据副本 |

## 练习题

1. 数据库是在实例里面，还是实例在数据库里面？
2. `DROP DATABASE` 会删除一张表还是整个数据库？
3. 删除数据库前为什么要确认连接目标？
4. 模式和数据库是一回事吗？

::: tip 提示
按“实例 > 数据库 > 模式 > 表”的顺序记。
:::

::: details 答案
1. 数据库在实例里面。
2. 整个数据库。
3. 避免连错环境或删错数据库。
4. 不是，模式在数据库里面。
:::

## 常见坑

- 把数据库和 PostgreSQL 服务混成一回事
- 删除前不确认当前环境
- 用数据库名区分环境但命名很相似
- 没有备份就执行删除

## 先记住这三句

- 数据库是实例里的数据空间。
- `DROP DATABASE` 影响整个数据库。
- 删除前先确认环境和备份。
