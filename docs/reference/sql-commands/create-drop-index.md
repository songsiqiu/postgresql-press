# CREATE INDEX 与 DROP INDEX 速查

`CREATE INDEX` 用来创建索引，`DROP INDEX` 用来删除索引。索引能加快部分查询，也会增加写入和维护成本。

## 你学完能干什么

- 能看懂创建普通索引的语法
- 知道索引适合服务查询条件
- 能理解删除索引前要确认依赖和影响
- 能避免“越多越好”的误解

## 创建索引

```sql
CREATE INDEX idx_notes_user_id
ON notes (user_id);
```

这类索引适合服务下面这种查询：

```sql
SELECT id, title
FROM notes
WHERE user_id = 10;
```

删除索引：

```sql
DROP INDEX idx_notes_user_id;
```

## 创建前先问

- 哪条查询慢？
- 慢查询的过滤条件是什么？
- 这列是否经常更新？
- 是否已经有类似索引？

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 索引 | 帮查询更快定位数据的结构 |
| 索引列 | 索引里包含的列 |
| 写入成本 | 插入、更新、删除时维护索引的成本 |
| 重复索引 | 作用高度重叠的索引 |

## 练习题

1. `CREATE INDEX` 一定会让所有查询变快吗？
2. `WHERE user_id = 10` 可能适合什么索引？
3. 索引会不会增加写入成本？
4. 删除索引前为什么要确认查询影响？

::: tip 提示
索引要从具体查询出发，不要看到字段就建。
:::

::: details 答案
1. 不一定。
2. `ON notes (user_id)` 这类索引。
3. 会。
4. 删除后相关查询可能变慢。
:::

## 常见坑

- 给每个字段都建索引
- 不看查询条件就建索引
- 重复创建作用类似的索引
- 删除索引前不看慢查询和执行计划

## 先记住这三句

- 索引服务具体查询。
- 索引会增加写入成本。
- 建索引前先看查询和执行计划。
