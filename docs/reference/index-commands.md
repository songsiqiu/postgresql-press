# 索引命令速查

索引命令用来创建、查看和删除索引。新手先掌握最常见的 `CREATE INDEX` 和 `DROP INDEX`，再理解唯一索引、并发建索引等场景。

## 你学完能干什么

- 能写出普通索引和唯一索引命令
- 知道删除索引不会删除表数据
- 能理解并发建索引为什么常用于生产环境
- 能避免不看查询就乱建索引

## 常用命令

```sql
CREATE INDEX idx_notes_user_id
ON notes (user_id);
```

创建唯一索引：

```sql
CREATE UNIQUE INDEX idx_users_email
ON users (email);
```

删除索引：

```sql
DROP INDEX idx_notes_user_id;
```

生产环境大表上建索引时，经常会关注：

```sql
CREATE INDEX CONCURRENTLY idx_notes_created_at
ON notes (created_at);
```

并发建索引耗时可能更长，但能减少对写入的阻塞。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 普通索引 | 帮助查询定位数据 |
| 唯一索引 | 帮助查询，同时保证值不重复 |
| 并发建索引 | 尽量减少建索引期间对写入的影响 |
| 删除索引 | 删除辅助结构，不删除表数据 |

## 练习题

1. 创建普通索引用哪个命令？
2. `DROP INDEX` 会删除表数据吗？
3. 邮箱不能重复时，可以考虑哪类索引或约束？
4. 大表生产环境建索引时，为什么会考虑 `CONCURRENTLY`？

::: tip 提示
索引命令要从真实查询和约束需求出发。
:::

::: details 答案
1. `CREATE INDEX`。
2. 不会。
3. 唯一索引或唯一约束。
4. 为了减少对正常写入的阻塞。
:::

## 常见坑

- 不看查询条件就建索引
- 忘记唯一索引会限制重复值
- 在生产大表上随意建索引
- 删除索引前不确认是否仍被查询依赖

## 先记住这三句

- 索引服务查询和约束。
- 删除索引不等于删除数据。
- 大表建索引要考虑业务影响。
