# 数值类型速查

数值类型用来保存整数、小数、金额和计数。选错数值类型，可能导致精度丢失或范围不够。

## 你学完能干什么

- 能区分整数和精确小数
- 知道金额优先考虑 `numeric`
- 能理解自增编号和普通整数的区别
- 能避免随手用浮点数保存金额

## 常见类型

| 类型 | 适合场景 |
| --- | --- |
| `integer` | 普通整数 |
| `bigint` | 大范围整数、编号、计数 |
| `numeric` | 金额、精确小数 |
| `real` / `double precision` | 科学计算、允许近似的小数 |
| `bigserial` | 自增大整数主键 |

## 一个例子

```sql
CREATE TABLE invoices (
  id bigserial PRIMARY KEY,
  amount numeric(12, 2) NOT NULL,
  item_count integer NOT NULL
);
```

`amount` 用 `numeric(12, 2)` 表示最多 12 位数字，其中 2 位是小数。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 精度 | 数字能准确保存到什么程度 |
| 范围 | 类型能保存的最大最小值 |
| 浮点数 | 近似小数，不适合金额 |
| 自增类型 | 自动从序列取值的整数类型 |

## 练习题

1. 金额字段优先考虑 `numeric` 还是浮点数？
2. 计数很大时，`bigint` 比 `integer` 更稳吗？
3. `bigserial` 适合做自增主键吗？
4. 浮点数适合保存必须精确的金额吗？

::: tip 提示
金额要精确，编号要看范围，近似计算才考虑浮点数。
:::

::: details 答案
1. `numeric`。
2. 更稳。
3. 适合。
4. 不适合。
:::

## 常见坑

- 金额用浮点数
- 自增主键范围选得太小
- 所有数字都用 `numeric`，忽略性能和用途
- 不区分业务编号和数据库主键

## 先记住这三句

- 金额用精确小数。
- 大编号用大整数。
- 浮点数不是精确金额类型。
