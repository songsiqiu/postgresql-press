# COPY 与批量导入

`COPY` 常用于批量导入导出数据。它比一条条 `INSERT` 更适合大量数据场景，但也更需要提前确认格式和目标表。

## 你学完能干什么

- 知道 `COPY` 适合什么场景
- 能理解服务端文件和客户端文件的差别
- 能列出导入前要检查的事项
- 不会把临时导出当完整备份

## 一个导入例子

```sql
COPY demo_tags (name)
FROM '/tmp/tags.csv'
WITH (FORMAT csv, HEADER true);
```

这表示从 CSV 文件导入 `name` 列。

在 `psql` 里也常见客户端侧命令：

```text
\copy demo_tags (name) FROM 'tags.csv' WITH (FORMAT csv, HEADER true)
```

新手先记住：`COPY` 和 `\copy` 的文件位置和权限语义不同，遇到权限问题要先确认文件在哪一侧。

## 导入前检查

- 目标表结构是否正确
- 文件编码是否匹配
- 分隔符、表头、空值表示是否正确
- 数据是否会违反约束
- 是否需要先在测试环境导入

## 练习题

1. 大量数据导入时，`COPY` 和一条条 `INSERT` 哪个更常见？
2. `\copy` 是 SQL 命令还是 `psql` 客户端命令？
3. 导入前为什么要检查约束？
4. 临时导出的 CSV 能当完整备份吗？

::: tip 提示
批量导入前先在小样本上试一遍，确认格式和约束都没问题。
:::

::: details 答案
1. `COPY` 更常见。
2. `psql` 客户端命令。
3. 违反约束会导致导入失败或部分数据无法写入。
4. 不能。
:::

## 常见坑

- 文件在本机，却用服务端 `COPY` 去读
- CSV 表头和列顺序不一致
- 导入前没检查唯一约束和外键

## 先记住这三句

- `COPY` 适合批量数据。
- `COPY` 和 `\copy` 文件位置不同。
- 导入前先查格式、编码和约束。
