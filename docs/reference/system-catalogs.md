# 系统目录与视图

系统目录和系统视图是 PostgreSQL 自己用来描述数据库状态的地方。新手不用背，但要知道它们能帮你查什么。

## 你学完能干什么

- 知道系统目录和普通业务表不同
- 能理解为什么很多工具能展示表、索引和连接信息
- 知道排查问题时可以查系统视图

## 可以查什么

| 想知道 | 可能查看的方向 |
| --- | --- |
| 当前连接 | 活动会话相关视图 |
| 表和索引 | 系统目录和信息模式 |
| 锁等待 | 锁和活动会话相关视图 |
| 配置值 | 设置相关视图 |
| 统计信息 | 统计相关视图 |

## 新手先记住

系统目录不是业务数据。不要随便修改系统目录，通常通过 SQL 命令和配置来改变数据库状态。

## 练习题

1. 系统目录主要保存什么信息？
2. 为什么不建议直接修改系统目录？
3. 排查锁等待时，系统视图能提供什么帮助？

::: tip 提示
先把系统目录理解成“数据库自己的说明书和状态表”。
:::

::: details 答案
1. 数据库对象、权限、配置、统计等内部信息。
2. 可能破坏数据库一致性，应该通过正式命令修改。
3. 可以看到会话、锁和等待关系等信息。
:::

## 常见坑

- 把系统视图当成业务表修改
- 不区分对象定义和运行状态
- 排查问题时只看应用日志，不看数据库状态

## 先记住这三句

- 系统目录描述数据库自己。
- 查可以，改要非常谨慎。
- 排查问题时，系统视图很有价值。
