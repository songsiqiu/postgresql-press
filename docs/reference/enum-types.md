# 枚举类型速查

枚举类型适合保存稳定、小范围、顺序明确的状态值。它能让数据库拒绝非法状态，但不适合频繁变化的业务字典。

## 你学完能干什么

- 知道什么时候可以用枚举类型
- 能创建一个简单枚举并用于表字段
- 知道枚举和字典表该怎么取舍

## 可运行例子

```sql
CREATE TYPE order_status AS ENUM ('pending', 'paid', 'shipped', 'cancelled');

CREATE TABLE demo_orders (
  id bigserial PRIMARY KEY,
  status order_status NOT NULL DEFAULT 'pending'
);

INSERT INTO demo_orders (status) VALUES ('paid');

SELECT id, status
FROM demo_orders
WHERE status = 'paid';
```

如果插入不在枚举列表里的值，数据库会拒绝。

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| 枚举类型 | 数据库类型，值来自固定列表 |
| 检查约束 | 在普通字段上限制允许值 |
| 字典表 | 用一张表维护可选项，更灵活 |
| 状态流转 | 业务上允许从一个状态变到另一个状态 |

## 练习题

1. 枚举适合频繁新增和删除的值吗？
2. 枚举能阻止非法值写入吗？
3. 如果状态需要后台配置，枚举和字典表更推荐哪个？
4. 枚举类型适合订单状态这种稳定值吗？

::: tip 提示
枚举适合“值很稳定”的场景；如果业务人员经常改选项，优先考虑字典表。
:::

::: details 答案
1. 不适合。
2. 能。
3. 字典表。
4. 适合，前提是状态集合稳定。
:::

## 常见坑

- 需求还没稳定就急着建枚举类型
- 把枚举当成状态机，忽略状态流转规则
- 需要多语言显示名时仍只靠枚举值本身
- 修改枚举前没评估迁移和发布顺序

## 先记住这三句

- 枚举适合稳定的小范围取值。
- 枚举能防止非法值进入表。
- 频繁变化的选项更适合字典表。
