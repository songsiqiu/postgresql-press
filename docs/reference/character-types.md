# 字符类型速查

字符类型用来保存文本。PostgreSQL 里新手最常用的是 `text`，只有明确长度规则时才考虑限制长度。

## 你学完能干什么

- 能区分 `text`、`varchar` 和 `char`
- 知道什么时候需要长度限制
- 能避免把所有业务规则都写成长度
- 能理解空字符串和 `NULL` 不同

## 常见类型

| 类型 | 新手解释 |
| --- | --- |
| `text` | 不限制长度的文本 |
| `varchar(n)` | 最多 n 个字符的文本 |
| `char(n)` | 固定长度文本，不常用于普通业务字段 |

## 一个例子

```sql
CREATE TABLE profiles (
  id bigserial PRIMARY KEY,
  display_name text NOT NULL,
  country_code char(2)
);
```

`display_name` 长度不固定，用 `text` 很自然；国家代码固定 2 位，可以用 `char(2)`。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 空字符串 | 长度为 0 的字符串 |
| `NULL` | 未知或缺失 |
| 长度限制 | 限制最多能存多少字符 |
| 固定长度 | 不足长度时也按固定长度处理 |

## 练习题

1. 长短不固定的普通文本优先考虑什么类型？
2. `varchar(20)` 表示最多多少个字符？
3. 空字符串和 `NULL` 是一回事吗？
4. `char(n)` 适合所有文本字段吗？

::: tip 提示
没有明确业务长度限制时，`text` 通常更简单。
:::

::: details 答案
1. `text`。
2. 20 个字符。
3. 不是。
4. 不适合。
:::

## 常见坑

- 没有业务原因也给所有字段限制长度
- 把空字符串当成 `NULL`
- 用 `char(n)` 保存普通名称
- 用文本保存本该有结构的数字、时间或 JSON

## 先记住这三句

- 普通文本优先考虑 `text`。
- 长度限制要有业务理由。
- 空字符串不是 `NULL`。
