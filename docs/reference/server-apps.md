# PostgreSQL 服务器应用速查

服务器应用是用来初始化、启动、停止、控制或维护 PostgreSQL 实例的工具。

## 你学完能干什么

- 知道哪些工具会影响数据库服务本身
- 能区分 `initdb`、`pg_ctl`、`postgres`
- 知道什么时候不该在生产机器上随手试命令

## 可运行例子

常见服务器工具：

| 工具 | 用途 |
| --- | --- |
| `initdb` | 初始化数据目录 |
| `pg_ctl` | 启动、停止、重载或查看服务状态 |
| `postgres` | PostgreSQL 服务器进程 |
| `pg_upgrade` | 做大版本升级 |
| `pg_controldata` | 查看数据目录控制信息 |

新手最常见的理解方式：

```text
initdb 准备数据目录 -> pg_ctl 管理服务 -> postgres 真正提供数据库服务
```

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| `initdb` | 初始化一个新的数据目录 |
| `pg_ctl` | 控制已有实例启动、停止或重载 |
| `postgres` | 数据库服务器进程 |
| `psql` | 客户端连接工具 |

## 练习题

1. 初始化数据目录常用哪个工具？
2. 管理服务启动停止常用哪个工具？
3. `psql` 属于服务器应用吗？

::: tip 提示
能影响实例生命周期的工具，要比普通查询工具更谨慎使用。
:::

::: details 答案
1. `initdb`。
2. `pg_ctl`。
3. 不属于，它是客户端应用。
:::

## 常见坑

- 在已有数据目录上误操作初始化命令
- 不理解重载和重启的区别
- 把服务器工具当成普通 SQL 工具

## 先记住这三句

- 服务器应用会影响 PostgreSQL 实例本身。
- `initdb` 是初始化，不是日常查询。
- 服务控制命令在生产环境要格外谨慎。
