# 翻译计划

这个项目不是一次性做完，而是按官方主线持续补齐。

## 你学完能干什么

- 知道本站后续怎么继续补内容
- 能判断一个章节是否达到新手友好标准
- 能避免只铺空页面、不补正文

## 先做什么

1. 完成站点骨架和目录映射
2. 先把新手最常看的章节补齐
3. 再按官方主线逐章补翻译
4. 每次补完都检查表达、链接和结构

## 章节完成标准

一篇正文页至少应该有：

- “你学完能干什么”
- 一个能照着跑或能看懂的例子
- 容易混淆的词或概念
- 3 到 5 道练习题
- 提示和答案
- 常见坑
- “先记住这三句”

## 补内容顺序

1. 先补主线入口，保证读者知道从哪开始
2. 再补核心章节，保证内容不是空壳
3. 然后补参考页，方便查命令、类型和函数
4. 最后按官方目录继续扩展细节

## 已补主线范围

- SQL 语言：查询、DDL、DML、事务、索引、JSON、分区、窗口函数等
- 服务器管理：安装、配置、权限、备份恢复、复制、监控、JIT、回归测试等
- 客户端接口：连接串、连接池、驱动、迁移、COPY、`libpq`、`ECPG` 等
- 服务端编程：函数、触发器、PL/pgSQL、扩展、FDW、SPI、逻辑解码、后台工作进程等
- 内部原理：查询执行、MVCC、WAL、锁、规划器、物理存储、协议、事务处理等
- 参考手册：SQL 命令、类型、函数、系统视图、客户端应用、服务器应用、网络地址、枚举、位串、XML、几何、对象标识符、复合类型等
- 附录：术语表、示例规范、SQL 兼容性、限制、缩略词表

## 练习题

1. 为什么不应该只铺很多空页面？
2. 一篇正文页至少要包含哪些学习辅助内容？
3. 后续继续补内容时，为什么要先看术语表？

::: tip 提示
翻译计划不是进度表装饰，而是防止内容越补越散。
:::

::: details 答案
1. 空页面不能帮助学习，只会让导航看起来完整。
2. 学习目标、例子、练习题、提示答案、常见坑、三句话总结等。
3. 保证同一个术语前后翻译一致。
:::

## 常见坑

- 只追求页面数量，不追求正文质量
- 每章结构都不一样，读者学习成本变高
- 术语不统一，后续难维护

## 先记住这三句

- 先补可读内容，再扩目录。
- 每章都要能让新手动手验证。
- 术语和示例要保持一致。
