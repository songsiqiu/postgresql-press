# COPY 流式接入

COPY 流式接入适合应用批量导入或导出大量数据。它比一条条插入更高效，但也更需要控制格式、事务和错误处理。

## 你学完能干什么

- 知道应用侧为什么会用 COPY
- 能理解流式导入和普通 INSERT 的区别
- 知道导入前要确认格式和字段顺序
- 能避免把脏数据直接灌进生产表

## 基本思路

普通批量插入：

```sql
INSERT INTO events (user_id, action)
VALUES (1, 'login'), (2, 'logout');
```

大量数据导入时，可以考虑 COPY：

```sql
COPY events (user_id, action)
FROM STDIN WITH (FORMAT csv);
```

应用通过驱动把数据流写入数据库。

## 常见注意点

- 字段顺序必须清楚
- CSV 转义规则要一致
- 大批量导入要考虑事务大小
- 先导入临时表再校验更稳
- 出错时要能定位到数据来源

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `COPY FROM` | 把数据导入表 |
| `COPY TO` | 把表数据导出 |
| `STDIN` | 从客户端流式输入 |
| 临时表 | 用来暂存和校验数据的表 |

## 练习题

1. 大量数据导入时，COPY 通常比一条条 INSERT 更适合吗？
2. `COPY FROM` 是导入还是导出？
3. 为什么建议先导入临时表再校验？
4. 字段顺序可以随便忽略吗？

::: tip 提示
COPY 很快，所以更要先确认格式和校验流程。
:::

::: details 答案
1. 通常更适合。
2. 导入。
3. 避免脏数据直接进入正式表。
4. 不可以。
:::

## 常见坑

- CSV 字段顺序和表字段不一致
- 没校验就导入正式表
- 单次事务太大，失败后回滚成本高
- 错误日志不足，无法定位坏数据

## 先记住这三句

- COPY 适合大量数据。
- 快导入更需要先校验。
- 字段顺序和格式必须明确。
