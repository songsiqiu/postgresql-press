# 取消查询

取消查询是在 SQL 执行太久、用户主动停止或系统达到边界时，让当前语句停止执行。它和断开连接不是一回事。

## 你学完能干什么

- 能区分取消查询和关闭连接
- 知道应用为什么要支持取消
- 能理解取消后需要处理错误
- 知道取消不是性能优化本身

## 常见场景

- 用户关闭报表页面
- 后台任务超过时间限制
- 管理员发现某条 SQL 影响系统
- 应用请求已经超时

取消查询后，数据库会停止当前语句，并返回错误给调用方。应用需要把这个错误处理清楚。

## 和超时的关系

超时可以自动触发取消。比如 `statement_timeout` 到达后，当前 SQL 会被取消。

手动取消则通常来自应用、驱动或管理员操作。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 取消查询 | 停止当前 SQL |
| 关闭连接 | 断开整个数据库连接 |
| 超时 | 等到指定时间后自动放弃 |
| 回滚 | 撤回事务里的未提交修改 |

## 练习题

1. 取消查询等于关闭连接吗？
2. `statement_timeout` 到达后通常会发生什么？
3. 查询被取消后，应用需要处理错误吗？
4. 取消查询能替代优化慢 SQL 吗？

::: tip 提示
取消查询是止损动作，不是把慢 SQL 变快。
:::

::: details 答案
1. 不等于。
2. 当前 SQL 被取消。
3. 需要。
4. 不能。
:::

## 常见坑

- 查询取消后应用还当成功处理
- 把取消查询当作性能优化
- 取消了语句却忘记处理事务状态
- 用户离开页面后后台 SQL 仍继续跑很久

## 先记住这三句

- 取消查询停止当前 SQL。
- 取消不等于断开连接。
- 取消后要处理错误和事务状态。
