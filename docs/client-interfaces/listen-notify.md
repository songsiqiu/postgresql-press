# LISTEN 与 NOTIFY

`LISTEN` 和 `NOTIFY` 提供一种轻量通知机制。它适合告诉应用“有事情发生了”，不适合替代可靠消息队列。

## 你学完能干什么

- 知道 `LISTEN` 和 `NOTIFY` 的基本作用
- 能理解通知不是持久消息
- 知道它适合轻量事件提醒
- 能避免把它当成完整消息系统

## 最小例子

一个连接监听频道：

```sql
LISTEN note_events;
```

另一个连接发送通知：

```sql
NOTIFY note_events, 'note_created';
```

监听方可以收到这个通知。

## 适合场景

- 缓存刷新提醒
- 管理后台轻量状态通知
- 数据变化后提醒应用重新拉取
- 开发工具或内部工具联动

通知内容应该尽量小。真正的数据通常让应用收到通知后再查询。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| `LISTEN` | 监听一个通知频道 |
| `NOTIFY` | 向频道发送通知 |
| 频道 | 通知的名字空间 |
| 负载 | 通知里附带的小段文本 |

## 练习题

1. `LISTEN` 是监听还是发送通知？
2. `NOTIFY` 适合发送大量可靠业务消息吗？
3. 收到通知后，应用通常应该直接拿它当完整数据吗？
4. 通知内容应该尽量大还是尽量小？

::: tip 提示
把 `NOTIFY` 想成提醒铃声，不要当成完整快递包裹。
:::

::: details 答案
1. 监听。
2. 不适合。
3. 不应该，通常再查询真实数据。
4. 尽量小。
:::

## 常见坑

- 把通知当成可靠消息队列
- 在通知负载里塞大量数据
- 监听连接断开后没有重连逻辑
- 收到通知后不重新查询真实状态

## 先记住这三句

- `LISTEN` 监听，`NOTIFY` 发送。
- 通知是轻量提醒。
- 它不能替代可靠消息队列。
