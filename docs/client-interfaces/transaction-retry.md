# 事务重试

事务重试是在并发冲突、序列化失败或临时错误后，重新执行整个事务。它不是简单地重发最后一条 SQL。

## 你学完能干什么

- 知道哪些错误适合重试
- 能理解事务重试要重跑完整业务单元
- 知道重试必须有次数和退避
- 能避免对不可重试错误盲目重试

## 为什么要重试

并发系统里，有些失败不是业务错，而是数据库为了保护一致性让某个事务失败。

常见可考虑重试的情况：

- 序列化失败
- 死锁被数据库打断
- 短暂连接或主备切换问题

但语法错误、权限错误、约束冲突通常不应该盲目重试。

## 重试边界

重试应该包住完整事务：

```text
开始事务
执行业务 SQL
提交
如果遇到可重试错误，整体重新来一次
```

不要只重试失败的最后一条 SQL，因为前面的读取结果可能已经过期。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 可重试错误 | 重新执行可能成功的临时失败 |
| 不可重试错误 | 重试也大概率失败的错误 |
| 退避 | 每次重试前等一小段时间 |
| 幂等 | 多次执行不会造成额外错误结果 |

## 练习题

1. 事务重试应该重试最后一条 SQL，还是整个事务？
2. 语法错误适合盲目重试吗？
3. 重试应该有没有次数上限？
4. 序列化失败是否可能适合重试？

::: tip 提示
重试的是一个完整业务动作，不是随手重发一句 SQL。
:::

::: details 答案
1. 整个事务。
2. 不适合。
3. 应该有。
4. 可能适合。
:::

## 常见坑

- 所有错误都自动重试
- 只重试最后一条 SQL
- 没有重试上限和等待策略
- 重试的业务动作不是幂等的

## 先记住这三句

- 事务重试要重跑完整事务。
- 不是所有错误都能重试。
- 重试必须有上限和退避。
