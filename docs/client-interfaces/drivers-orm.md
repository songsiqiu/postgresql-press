# 驱动与 ORM 选择

应用连接 PostgreSQL 通常会用数据库驱动，也可能用 ORM。新手先理解它们各自解决什么问题，再决定怎么选。

## 你学完能干什么

- 知道驱动和 ORM 的区别
- 能理解为什么 ORM 不能替代 SQL 基础
- 能判断什么时候需要写原生 SQL
- 知道选择工具时要看事务、连接池和迁移支持

## 驱动是什么

驱动负责让应用和 PostgreSQL 通信。它通常提供连接、参数绑定、执行 SQL、读取结果这些能力。

你可以把驱动理解成应用和数据库之间的基础通道。

## ORM 是什么

ORM 会把表和对象做映射，让你用更接近应用语言的方式操作数据。

它能减少一部分重复代码，但复杂查询、性能分析和事务边界仍然需要你懂 SQL。

## 选择时看什么

| 维度 | 要看什么 |
| --- | --- |
| 连接池 | 是否和应用运行方式匹配 |
| 参数绑定 | 是否默认支持安全参数 |
| 事务 | 是否能清楚控制事务边界 |
| 迁移 | 是否支持结构变更管理 |
| 原生 SQL | 遇到复杂查询时是否容易落回 SQL |

## 练习题

1. 驱动主要解决什么问题？
2. ORM 能让你完全不学 SQL 吗？
3. 为什么复杂查询有时要写原生 SQL？
4. 选择工具时为什么要看事务支持？

::: tip 提示
工具能提效，但不能替你理解数据结构、事务和 SQL。
:::

::: details 答案
1. 让应用连接并操作 PostgreSQL。
2. 不能。
3. ORM 表达复杂查询可能不清楚，也不利于性能分析。
4. 多步业务操作需要明确一起提交或回滚。
:::

## 常见坑

- 以为用了 ORM 就不用理解 SQL
- 复杂查询硬用 ORM 拼到很难维护
- 不看连接池和事务行为就上线

## 先记住这三句

- 驱动是基础通道。
- ORM 是抽象，不是 SQL 替代品。
- 工具选择要看事务、连接和可维护性。
