# 应用开发注意点

应用连 PostgreSQL 时，重点不是把 SQL 藏起来，而是把连接、事务和参数处理好。

## 你学完能干什么

- 知道为什么要用参数化查询
- 能理解事务应该放在业务动作边界
- 能避免把数据库连接用成一次性资源

## 参数化查询

不要把用户输入直接拼到 SQL 字符串里。应该使用驱动提供的参数化能力。

错误思路：

```text
SELECT * FROM users WHERE name = '用户输入'
```

正确思路：

```text
SELECT * FROM users WHERE name = $1
```

这里的 `$1` 由驱动绑定真实参数。

## 事务边界

事务应该围绕一个完整业务动作。比如创建订单时，订单、订单明细、库存扣减要保持一致，就应该放在同一个事务里。

## 练习题

1. 为什么不能直接拼接用户输入到 SQL？
2. 创建订单时为什么常常需要事务？
3. 一个接口结束后，数据库连接应该怎么处理？

::: tip 提示
应用层最容易出错的不是 SQL 语法，而是输入、事务和连接生命周期。
:::

::: details 答案
1. 可能造成 SQL 注入，也容易因为特殊字符导致语句错误。
2. 多张表的修改要一起成功或一起失败。
3. 归还给连接池，而不是泄漏不释放。
:::

## 常见坑

- 拼接 SQL 字符串处理用户输入
- 一个事务里做太多慢操作
- 忘记释放连接或归还连接池

## 先记住这三句

- 用户输入必须参数化。
- 事务跟着业务动作走。
- 连接要复用，也要及时归还。
