# 连接串

连接串把数据库地址、端口、库名、用户和连接参数放在一起。它是应用连接 PostgreSQL 最常见的入口之一。

## 你学完能干什么

- 能看懂 URI 形式的连接串
- 知道连接串里常见字段代表什么
- 能理解密码和敏感参数要妥善保存
- 能避免把连接串硬编码到代码仓库

## URI 形式

```text
postgresql://app_user:secret@db.example.com:5432/app_db?sslmode=require
```

可以拆成：

| 部分 | 含义 |
| --- | --- |
| `app_user` | 用户名 |
| `secret` | 密码 |
| `db.example.com` | 主机地址 |
| `5432` | 端口 |
| `app_db` | 数据库名 |
| `sslmode=require` | 连接参数 |

## 安全建议

- 不把生产连接串提交到代码仓库
- 用环境变量或密钥管理系统保存
- 给不同环境使用不同账号
- 不在日志里完整打印连接串

## 应用里怎么写

推荐让应用只读取一个入口：

```bash
DATABASE_URL="postgresql://app_user:secret@db.example.com:5432/app_db?sslmode=require"
```

代码里只引用环境变量：

```js
const databaseUrl = process.env.DATABASE_URL
```

记录日志时不要直接输出完整连接串，可以只输出主机、数据库名和连接参数摘要。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 连接串 | 描述如何连接数据库的一串信息 |
| DSN | 数据源名称，常用来指连接配置 |
| 参数 | 控制连接行为的附加设置 |
| `sslmode` | 客户端 SSL 连接要求 |

## 练习题

1. 连接串里通常包含主机和端口吗？
2. 生产连接串适合直接提交到代码仓库吗？
3. `sslmode=require` 属于连接参数吗？
4. 不同环境是否应该尽量使用不同账号？

::: tip 提示
连接串既是配置，也是敏感信息。
:::

::: details 答案
1. 包含。
2. 不适合。
3. 属于。
4. 应该。
:::

## 常见坑

- 把生产密码写进仓库
- 日志里打印完整连接串
- 开发、测试、生产共用账号
- 连接参数写在多个地方，口径不一致
- 本地临时连接串混进生产部署配置

## 先记住这三句

- 连接串说明怎么连数据库。
- 连接串通常包含敏感信息。
- 不同环境要分开管理。
