# 数据库迁移工具

数据库迁移工具用来管理表结构变化。它解决的是“结构怎么一步步从旧版本变到新版本”的问题。

## 你学完能干什么

- 知道迁移文件为什么重要
- 能理解向前迁移和回滚的区别
- 知道上线前要评估表大小、锁和数据兼容
- 不会直接在生产库手工改结构后忘记记录

## 迁移文件做什么

迁移文件通常记录一组结构变更，比如：

```sql
ALTER TABLE notes
ADD COLUMN archived boolean NOT NULL DEFAULT false;
```

它让团队知道数据库结构是怎么变化的，也方便不同环境保持一致。

## 上线前要看什么

- 表数据量有多大
- 是否会长时间锁表
- 默认值和非空约束是否影响已有数据
- 应用新旧版本是否兼容
- 失败后怎么回滚

## 回滚不是万能的

删字段、删表、改类型这类操作可能丢数据。即使迁移工具提供回滚入口，也不代表业务上一定能安全回滚。

## 应用里怎么写迁移

给大表加字段时，尽量把“结构变化”和“数据回填”拆开：

```sql
ALTER TABLE notes
ADD COLUMN archived boolean;
```

应用兼容新旧字段后，再分批回填：

```sql
UPDATE notes
SET archived = false
WHERE archived IS NULL
  AND id BETWEEN 1 AND 10000;
```

确认数据都满足要求后，再考虑加 `NOT NULL` 和默认值：

```sql
ALTER TABLE notes
ALTER COLUMN archived SET DEFAULT false;

ALTER TABLE notes
ALTER COLUMN archived SET NOT NULL;
```

这样做比一次性在大表上做重变更更容易控制风险。

## 练习题

1. 迁移文件主要记录什么？
2. 为什么生产库不建议手工改完不记录？
3. 加 `NOT NULL` 字段前要考虑什么？
4. 回滚一定安全吗？

::: tip 提示
迁移不是“能执行 SQL 就行”，还要考虑数据、锁、应用兼容和回滚。
:::

::: details 答案
1. 数据库结构变化。
2. 环境会不一致，团队也追踪不到结构变化来源。
3. 已有数据是否满足要求，默认值和锁影响。
4. 不一定，涉及数据丢失的操作很难安全回滚。
:::

## 常见坑

- 手工改生产库，没有迁移记录
- 在线上大表上直接加重锁变更
- 只写向前迁移，不考虑失败处理
- 应用还没兼容新结构，就先上线破坏性迁移

## 先记住这三句

- 迁移文件记录结构变化。
- 上线前要评估锁和数据兼容。
- 回滚不是万能安全网。
