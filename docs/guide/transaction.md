# 事务与并发

事务解决的是一个很实际的问题：一组数据库操作要么一起成功，要么一起失败。

## 一个最小事务

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

UPDATE accounts
SET balance = balance + 100
WHERE id = 2;

COMMIT;
```

转账就是典型例子。扣款和加款必须一起成功。中间任何一步出错，都应该回滚：

```sql
ROLLBACK;
```

## 为什么会有锁

当两个人同时改同一行数据时，PostgreSQL 必须决定谁先改、谁等待。锁不是异常情况，而是数据库保证数据正确的一部分。

新手可以先记住：

- 读数据通常不会挡住别人读
- 修改同一行数据时可能等待
- 等待太久时要检查事务有没有长时间不提交
- 不要在事务里做太多和数据库无关的事情

## 什么是可见性

PostgreSQL 使用多版本并发控制。简单说，一个事务看到的数据，可能和另一个事务正在修改但还没提交的数据不同。

这能让读写更少互相阻塞，但也意味着你要理解“提交之前，别人不一定看得到你的修改”。

## 新手建议

- 事务尽量短
- 出错时明确回滚
- 批量修改前先用 `SELECT` 确认范围
- 遇到等待，先查有没有长事务
