# 逻辑解码

逻辑解码可以把 WAL 里的变化转换成更容易被外部系统理解的数据变更流。它是逻辑复制、订阅和数据同步工具背后的重要能力。

## 你学完能干什么

- 知道逻辑解码和 WAL 有关系
- 能理解它为什么能服务数据同步
- 知道复制槽会影响 WAL 保留
- 能避免把逻辑解码当成普通查询功能

## 一个直觉例子

普通查询是主动问数据库：

```sql
SELECT *
FROM orders
WHERE id = 10;
```

逻辑解码更像是读取变化：

```text
订单表插入了一行
订单表更新了一行
订单表删除了一行
```

外部同步工具可以根据这些变化，把数据同步到搜索、缓存或其他数据库。

## 需要关注什么

- 是否启用了合适的 WAL 级别
- 复制槽是否长期堆积
- 下游消费是否及时
- 解码输出格式由插件决定

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 逻辑解码 | 把 WAL 变化解读成逻辑数据变更 |
| WAL | 数据库变更日志 |
| 复制槽 | 保留下游还没消费的 WAL |
| 输出插件 | 决定变化以什么格式输出 |

## 练习题

1. 逻辑解码和 WAL 有没有关系？
2. 复制槽长期没人消费会有什么风险？
3. 逻辑解码适合替代普通 `SELECT` 查询吗？
4. 输出格式通常由什么决定？

::: tip 提示
逻辑解码关注的是“数据发生了什么变化”，不是“现在查出来是什么结果”。
:::

::: details 答案
1. 有。
2. WAL 可能不断保留，占用磁盘。
3. 不适合。
4. 输出插件。
:::

## 常见坑

- 开了复制槽但没有监控消费进度
- 把逻辑解码当成普通查询接口
- 忽略 WAL 保留导致磁盘增长
- 没确认下游能处理重复或延迟事件

## 先记住这三句

- 逻辑解码读取变化。
- 复制槽要监控消费进度。
- 它常用于同步，不是普通查询替代品。
