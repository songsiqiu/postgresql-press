# 后台工作进程

后台工作进程是 PostgreSQL 服务器内部或扩展里长期运行的工作单元。它们可以在数据库服务里做异步、周期性或辅助性任务。

## 你学完能干什么

- 知道后台工作进程不是普通客户端连接
- 能理解扩展为什么可能启动后台任务
- 知道新手阶段不应随意写服务器后台进程

## 可运行例子

你可以先把它理解成：

```text
普通应用连接：外部程序连进数据库执行 SQL
后台工作进程：数据库服务器内部运行的工作进程
```

一些数据库内部任务或扩展能力，可能依赖后台进程长期工作。

## 可照着理解：什么时候会看到它

查看当前活动：

```sql
SELECT pid, backend_type, state
FROM pg_stat_activity
ORDER BY backend_type, pid;
```

你可能会看到 `autovacuum worker`、`logical replication worker` 等后台类型。它们不是普通业务连接，但会消耗资源，也可能影响排障判断。

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| 后台工作进程 | 数据库服务器内部运行的工作进程 |
| 客户端连接 | 应用或工具从外部连接数据库 |
| autovacuum | PostgreSQL 自动清理和维护统计信息的后台能力 |
| 扩展 | 可以增加服务器能力的组件 |

## 练习题

1. 后台工作进程是在客户端机器上运行的吗？
2. 普通业务应用是否应该优先通过后台工作进程写业务逻辑？
3. 为什么扩展可能需要后台进程？

::: tip 提示
后台工作进程属于服务器内部能力，学习顺序上应放在函数、触发器、扩展之后。
:::

::: details 答案
1. 不是，它运行在数据库服务器侧。
2. 不应该。普通业务逻辑优先放在应用服务或清晰的数据库函数里。
3. 因为有些扩展需要长期执行异步或周期性任务。
:::

## 常见坑

- 把后台工作进程当作普通定时任务工具
- 用服务器内部能力承载不该放进数据库的业务流程
- 没考虑崩溃、权限、升级和运维成本
- 排查连接数时，把后台进程和应用连接混在一起

## 先记住这三句

- 后台工作进程运行在数据库服务器内部。
- 它适合底层能力，不适合新手随手写业务逻辑。
- 先学清楚扩展边界，再深入后台进程。
