# 扩展与过程语言

PostgreSQL 的扩展能力很强，可以安装扩展，也可以使用过程语言写更复杂的函数。

## 你学完能干什么

- 知道扩展是什么
- 能理解为什么安装扩展需要权限和评估
- 知道过程语言适合解决什么问题

## 扩展是什么

扩展可以给 PostgreSQL 增加额外能力。比如常见扩展可能提供新的函数、类型、索引能力或统计能力。

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

这类语句通常需要有足够权限才能执行。

## 可照着跑：检查扩展是否安装

```sql
SELECT extname, extversion
FROM pg_extension
ORDER BY extname;
```

安装扩展前，先确认它解决什么问题、谁维护、是否需要额外配置、升级时是否兼容。

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

安装后还要确认它是否真的可用，而不是只看命令成功。

## 过程语言是什么

过程语言让你用 SQL 之外的语言写数据库函数。常见场景是逻辑比单条 SQL 更复杂，需要条件判断、循环或异常处理。

## 练习题

1. 扩展会给 PostgreSQL 增加什么？
2. 为什么不能随便在生产库安装扩展？
3. 什么时候会考虑过程语言？

::: tip 提示
扩展是“给数据库加能力”，不是普通业务配置。
:::

::: details 答案
1. 新函数、新类型、新索引能力、统计能力等。
2. 可能影响权限、安全、升级和运维，需要评估。
3. 当函数逻辑超出普通 SQL 表达能力时。
:::

## 常见坑

- 在生产环境随手安装没评估过的扩展
- 把过程语言当成应用层替代品
- 忽略扩展版本和数据库版本的兼容关系
- 迁移到新环境时忘记安装同样扩展

## 先记住这三句

- 扩展会改变数据库能力边界。
- 生产环境安装扩展要先评估。
- 过程语言适合少量靠近数据的复杂逻辑。
