# 自定义类型基础

PostgreSQL 允许创建自定义类型。它能让数据表达更贴近业务，但也会增加维护成本。

## 你学完能干什么

- 知道自定义类型能解决什么问题
- 能区分枚举类型、复合类型和域的大致用途
- 知道什么时候先不要自定义类型

## 常见类型

| 类型 | 新手理解 |
| --- | --- |
| 枚举类型 | 一组固定取值 |
| 复合类型 | 多个字段组合成一个类型 |
| 域 | 在已有类型上加约束 |

## 域的例子

```sql
CREATE DOMAIN positive_amount AS numeric
CHECK (VALUE > 0);
```

之后可以把 `positive_amount` 当成一种类型使用，数据库会检查值必须大于 0。

## 什么时候适合

- 规则稳定
- 多张表复用同一类约束
- 希望数据库层明确表达业务含义

## 什么时候慎用

- 业务规则还在频繁变化
- 只是为了让建表看起来更高级
- 应用和迁移工具对自定义类型支持不好

## 练习题

1. 域是在已有类型上加什么？
2. 枚举类型适合频繁变化的取值吗？
3. 为什么自定义类型会增加维护成本？
4. `positive_amount` 这个域限制了什么？

::: tip 提示
自定义类型要服务稳定规则，不要为了抽象而抽象。
:::

::: details 答案
1. 约束。
2. 不太适合。
3. 迁移、兼容、工具支持和规则变更都要额外考虑。
4. 数值必须大于 0。
:::

## 常见坑

- 规则没稳定就创建自定义类型
- 自定义类型太多，迁移变复杂
- 本来简单的字段被过度抽象

## 先记住这三句

- 自定义类型表达稳定规则。
- 域适合复用约束。
- 先确认维护成本，再决定是否创建。
