# 规则、通知与事件

PostgreSQL 除了函数和触发器，还有规则、通知和事件触发器等能力。新手先知道它们存在和大致用途即可。

## 你学完能干什么

- 知道规则、通知、事件触发器大概解决什么问题
- 能理解这些能力为什么不适合一开始就滥用
- 能在读官方文档时不被术语吓住

## 通知是什么

通知机制可以让一个会话发出消息，另一个正在监听的会话收到消息。

常见语句：

```sql
NOTIFY channel_name, 'payload';
```

它适合轻量通知，不适合当成完整消息队列系统来用。

## 规则是什么

规则可以重写查询行为。它比较底层，理解和维护成本更高。新手阶段知道它存在即可，日常更常见的是视图、函数和触发器。

## 事件触发器是什么

事件触发器关注数据库对象变化，比如执行某些 DDL 时触发。它更偏管理和审计场景。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 通知 | 会话之间发一个轻量消息 |
| 规则 | 重写某些 SQL 行为 |
| 事件触发器 | 在数据库对象变化时触发逻辑 |
| 普通触发器 | 在表数据插入、更新、删除时触发逻辑 |

## 练习题

1. `NOTIFY` 更适合轻量通知还是完整消息队列？
2. 普通触发器和事件触发器关注点有什么不同？
3. 为什么新手不建议一开始大量使用规则？

::: tip 提示
这些能力都偏进阶。先会函数、触发器和扩展，再慢慢看它们。
:::

::: details 答案
1. 轻量通知。
2. 普通触发器关注表数据变化，事件触发器关注数据库对象变化。
3. 规则会改变 SQL 行为，理解和维护成本较高。
:::

## 常见坑

- 把 `NOTIFY` 当成可靠消息队列
- 不理解规则就修改查询行为
- 用事件触发器隐藏管理逻辑，后续排查困难

## 先记住这三句

- 通知是轻量消息，不是完整队列。
- 规则很强，但也更难维护。
- 事件触发器更偏管理和审计。
