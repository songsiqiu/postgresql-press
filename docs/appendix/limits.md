# PostgreSQL 限制

PostgreSQL 限制说明数据库对象、字段、行大小、参数等能力边界。新手不用背数字，但要知道“数据库也有边界”。

## 你学完能干什么

- 知道限制页适合在设计前查
- 能判断哪些问题可能和对象数量或字段大小有关
- 不会把数据库当成没有上限的容器

## 可运行例子

设计表结构前，可以先问三个问题：

```text
这一列会不会非常大？
这张表会不会有特别多列？
这个对象命名会不会太长？
```

如果答案是“可能会”，就该查 PostgreSQL 限制和对应章节，而不是上线后再碰边界。

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| 限制 | PostgreSQL 能支持的边界 |
| 配置参数 | 可以调整的运行设置 |
| 性能瓶颈 | 没到硬限制但已经变慢 |
| 设计约束 | 业务自己规定的边界 |

## 练习题

1. 限制页适合什么时候查？
2. 性能变慢是否一定说明碰到了 PostgreSQL 硬限制？
3. 字段可能特别大时，应该联想到哪个存储机制？

::: tip 提示
限制不是日常背诵表，更多是设计和排障时的检查入口。
:::

::: details 答案
1. 表结构、对象命名、字段大小等设计前，或排查边界问题时。
2. 不一定，可能只是索引、SQL、配置或数据分布问题。
3. TOAST。
:::

## 常见坑

- 等生产报错后才查限制
- 把性能问题都归因成硬限制
- 没给业务字段设计合理边界

## 先记住这三句

- PostgreSQL 很强，但不是没有边界。
- 限制页是设计前和排障时的检查入口。
- 大字段、超多列、超长命名都要提前确认。
