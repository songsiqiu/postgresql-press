# 练习与示例规范

这个站点后续每章都要能让新手动手做，而不是只看文字。

## 你学完能干什么

- 知道本站练习题应该怎么写
- 知道哪些章节适合做沙盒
- 能保持示例风格一致

## 每章练习题规则

- 每章 3 到 5 题
- 题目要能在读完当前页后完成
- 尽量配提示和答案
- 不考冷门细节，优先考真实使用场景

## 关键章节动手区

适合加动手区的章节：

- SQL 查询
- 数据修改
- 事务
- 索引与性能

不适合每章都做完整沙盒。参考、术语、目录类页面以练习题为主。

## 示例数据规则

示例尽量使用同一组表名，减少新手理解成本：

| 表名 | 用途 |
| --- | --- |
| `demo_users` | 用户 |
| `notes` | 笔记 |
| `accounts` | 账户和转账 |
| `demo_tags` | 标签 |
| `orders` | 订单 |
| `inventory` | 库存 |
| `events` | JSON 事件 |

## 示例输出规则

- 查询示例尽量给出小表格结果
- 修改示例要说明修改前后有什么变化
- 性能和内部原理示例可以用“模拟结果”，但要明确是帮助理解的简化场景
- 不要为了示例自行省略后端返回的数字或时间精度

## 练习题

1. 为什么每章练习题不宜太多？
2. 哪些章节最适合做动手区？
3. 为什么示例表名要尽量统一？
4. 查询示例为什么最好给出结果？

::: tip 提示
练习的目标是让读者马上验证理解，不是把读者卡住。
:::

::: details 答案
1. 太多会打断学习节奏，3 到 5 题更容易完成。
2. SQL、事务、索引、查询等能观察结果变化的章节。
3. 读者不用每页重新理解一套业务背景。
4. 新手可以对照自己执行后的输出，确认理解是否正确。
:::

## 常见坑

- 练习题脱离本章内容
- 答案只给结果，不解释关键原因
- 每章都硬做复杂沙盒，维护成本太高

## 先记住这三句

- 练习要短、准、能做。
- 沙盒只放在最适合动手的章节。
- 示例命名统一，新手读起来更轻松。
