# 认证与访问规则

认证决定“谁能连进来”，权限决定“连进来以后能做什么”。这两件事相关，但不是一回事。

## 你学完能干什么

- 能区分认证和授权
- 知道连接失败时要检查访问规则
- 能理解为什么同一个用户在不同来源可能结果不同
- 知道不要为了省事放开所有访问

## 认证和授权的区别

| 主题 | 解决什么问题 |
| --- | --- |
| 认证 | 你是谁，能不能连进来 |
| 授权 | 你连进来后能做什么 |

比如一个用户密码正确，说明它可能通过认证；但它是否能查询某张表，还要看权限。

## 访问规则看什么

连接 PostgreSQL 时通常要同时满足：

- 地址和端口能访问
- 数据库名正确
- 用户名和认证方式匹配
- 来源地址被允许
- 密码或证书等凭据正确

## 新手常见现象

| 现象 | 可能方向 |
| --- | --- |
| 本机能连，远程不能连 | 监听地址、防火墙、访问规则 |
| 密码正确但仍失败 | 用户、数据库、来源规则不匹配 |
| 能连上但不能查表 | 权限问题，不是认证问题 |

## 排障步骤：远程连接失败

1. 先确认 PostgreSQL 是否监听了远程地址。
2. 再确认服务器防火墙是否允许数据库端口。
3. 然后检查访问规则是否允许这个来源地址、数据库和用户组合。
4. 最后用同一个用户、同一个库名、同一个来源再试一次。

常见检查入口：

```sql
SHOW listen_addresses;
SHOW port;
SELECT current_user;
```

如果本机能连、远程不能连，通常优先查监听地址、防火墙和访问规则；如果能连上但查不了表，再去查权限。

## 练习题

1. 认证和授权是一回事吗？
2. 能连上数据库但不能查表，更可能是哪类问题？
3. 本机能连远程不能连，应该先查哪些方向？
4. 为什么不要为了省事放开所有来源访问？

::: tip 提示
先判断问题发生在“连接前”还是“连接后”，排查会快很多。
:::

::: details 答案
1. 不是。认证管能不能连，授权管能做什么。
2. 授权或对象权限问题。
3. 监听地址、防火墙、访问规则、网络连通性。
4. 会扩大攻击面，带来安全风险。
:::

## 常见坑

- 把权限错误当成密码错误
- 为了联调直接放开所有地址
- 只改数据库用户，不看来源访问规则
- 改了访问规则后，没有确认是否已经重载配置

## 先记住这三句

- 认证管入口，授权管能力。
- 连接问题先分清发生在连接前还是连接后。
- 访问规则越宽，安全风险越大。
