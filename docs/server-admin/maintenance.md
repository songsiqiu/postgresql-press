# 日常维护

数据库不是装好就不用管。日常维护的目标是让它稳定、可恢复、可观察。

## 你学完能干什么

- 知道日常要关注哪些数据库状态
- 能理解备份、统计信息、膨胀和连接数为什么重要
- 能给小团队列出一份基础巡检清单

## 基础巡检清单

| 项目 | 要看什么 |
| --- | --- |
| 备份 | 最近一次备份是否成功，是否做过恢复演练 |
| 连接数 | 是否长期接近上限 |
| 慢查询 | 是否有持续变慢的 SQL |
| 表大小 | 哪些表增长最快 |
| 锁等待 | 是否频繁出现长时间等待 |
| 磁盘 | 数据目录所在磁盘是否足够 |

## 统计信息

PostgreSQL 需要统计信息来估算查询成本。数据变化很多时，统计信息不准，执行计划也可能变差。

新手先记住：如果表数据量变化很大，性能突然异常，就要考虑统计信息是否需要更新。

## 练习题

1. 为什么备份不能只看“有没有文件”？
2. 连接数长期接近上限可能说明什么？
3. 表数据变化很大后，为什么可能影响查询计划？

::: tip 提示
维护不是每天手动敲很多命令，而是有固定清单，发现异常再深入。
:::

::: details 答案
1. 还要确认备份能不能恢复。
2. 可能连接池配置不合理、应用没释放连接，或并发压力过大。
3. 统计信息可能不准，数据库会选错执行方式。
:::

## 常见坑

- 只做备份，从不恢复演练
- 把连接数打满当成数据库性能差
- 表变大后还按小表思路写查询

## 先记住这三句

- 备份要能恢复才算数。
- 连接、磁盘、慢查询要长期看趋势。
- 数据量变了，性能判断也要跟着变。
