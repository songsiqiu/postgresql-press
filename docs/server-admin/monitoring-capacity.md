# 监控与容量

监控和容量管理解决的是“数据库现在是否健康、未来是否撑得住”的问题。

## 你学完能干什么

- 知道数据库监控要看哪些基础指标
- 能区分连接、磁盘、慢查询、锁等待这些问题
- 能理解容量规划为什么要看趋势
- 能列出一份新手可用的巡检清单

## 基础监控项

| 监控项 | 说明 |
| --- | --- |
| 连接数 | 当前连接是否接近上限 |
| 磁盘空间 | 数据目录和日志所在磁盘是否充足 |
| 慢查询 | 是否有越来越慢的 SQL |
| 锁等待 | 是否有长时间等待的事务 |
| 表大小 | 哪些表增长最快 |
| 复制延迟 | 从库是否跟得上主库 |

## 容量怎么看

容量不要只看某一天的数字，要看趋势：

- 表每周增长多少
- 磁盘还能撑多久
- 慢查询是否变多
- 连接数峰值是否越来越接近上限

## 小型巡检模板

1. 今天备份是否成功
2. 磁盘是否足够
3. 是否有长事务或锁等待
4. 是否出现新的慢查询
5. 表增长是否异常

## 操作步骤：每天 5 分钟巡检

下面这些 SQL 不替代完整监控系统，但适合新手先建立排查手感。

查看当前连接状态：

```sql
SELECT state, count(*)
FROM pg_stat_activity
GROUP BY state
ORDER BY count(*) DESC;
```

查看长事务：

```sql
SELECT pid, usename, state, now() - xact_start AS xact_age, query
FROM pg_stat_activity
WHERE xact_start IS NOT NULL
ORDER BY xact_age DESC
LIMIT 5;
```

查看大表：

```sql
SELECT relname, pg_size_pretty(pg_total_relation_size(relid)) AS total_size
FROM pg_catalog.pg_statio_user_tables
ORDER BY pg_total_relation_size(relid) DESC
LIMIT 10;
```

这些结果要连续看趋势。今天第一名的大表不一定有问题，但一周内突然暴涨就值得查。

## 练习题

1. 为什么容量规划要看趋势？
2. 连接数接近上限可能有哪些原因？
3. 表增长过快时应该先确认什么？
4. 从库复制延迟变大可能影响什么？

::: tip 提示
监控不是为了堆图表，而是为了比用户更早发现问题。
:::

::: details 答案
1. 单点数字看不出未来什么时候会耗尽资源。
2. 并发升高、连接池过大、连接泄漏、慢事务占用连接。
3. 是否有业务增长、异常写入、日志或历史数据未清理。
4. 读从库的数据可能变旧，故障切换风险也会变高。
:::

## 常见坑

- 只看 CPU，不看连接、锁和慢查询
- 等磁盘快满了才处理
- 只看当前值，不看增长趋势
- 巡检 SQL 查到了异常，却没有记录时间和当时业务背景

## 先记住这三句

- 监控要覆盖连接、磁盘、SQL、锁和复制。
- 容量管理看趋势，不只看今天。
- 巡检清单越固定，越不容易漏。
