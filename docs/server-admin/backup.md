# 备份与恢复

这一页会讲清楚什么时候该备份、怎么备份、怎么恢复，以及恢复前要确认什么。

## 你学完能干什么

- 知道备份不等于恢复成功
- 能区分逻辑备份和物理备份的大致用途
- 能列出恢复前必须确认的事项

## 备份先问三个问题

1. 要备份一个库，还是整个实例？
2. 要恢复到某个文件，还是恢复成可运行的数据库？
3. 能接受丢多少数据、停多久服务？

## 常见备份方式

| 方式 | 适合场景 |
| --- | --- |
| 逻辑备份 | 导出库或表，适合迁移、较小数据量、结构审查 |
| 物理备份 | 保存数据库文件级别内容，适合完整恢复和较大实例 |
| 持续归档 | 配合恢复到某个时间点 |

## 恢复前检查

- 目标环境是不是正确
- 是否会覆盖已有数据
- 备份文件是否完整
- 版本和扩展是否兼容
- 是否有人正在使用目标库

## 练习题

1. 为什么“有备份文件”不代表安全？
2. 迁移一小部分表时，更可能先考虑哪类备份？
3. 恢复前为什么要确认目标环境？

::: tip 提示
备份的价值要靠恢复验证，不靠文件名看起来像备份。
:::

::: details 答案
1. 文件可能损坏、过期，或者根本不能成功恢复。
2. 逻辑备份。
3. 防止把数据恢复到错误环境，覆盖不该覆盖的数据。
:::

## 常见坑

- 只备份，从不做恢复演练
- 恢复前没有确认目标库
- 忽略扩展和版本差异

## 先记住这三句

- 不能恢复的备份不算真正可靠。
- 恢复比备份更需要谨慎。
- 先确认环境，再执行恢复。
