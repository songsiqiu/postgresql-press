# 导入导出与迁移

导入导出和迁移是数据库管理中很常见的工作。新手先分清“拷贝数据”“备份恢复”“版本迁移”不是一回事。

## 你学完能干什么

- 知道什么时候用导入导出，什么时候用备份恢复
- 能理解迁移前要确认版本、扩展和权限
- 能列出迁移前后的检查事项

## 常见场景

| 场景 | 说明 |
| --- | --- |
| 导出一张表 | 给分析、排查、临时处理使用 |
| 导入一批数据 | 从文件导入初始化数据或业务数据 |
| 迁移一个库 | 把数据从一个环境搬到另一个环境 |
| 升级版本 | 数据库主版本变化，需要更谨慎评估 |

## 导入导出和备份的区别

导入导出通常面向部分数据或数据交换。备份恢复面向灾难恢复和完整数据保护。

不要把临时导出的 CSV 当成数据库备份。

## 迁移前检查

- 源库和目标库版本
- 扩展是否一致
- 角色和权限是否准备好
- 字符集和时区设置
- 数据量和停机窗口
- 回滚方案

## 操作步骤：导出并导入一张表

导出：

```sql
\copy notes(id, user_id, body) TO 'notes.csv' WITH (FORMAT csv, HEADER true)
```

导入前先放进临时表或中间表：

```sql
CREATE TEMP TABLE import_notes (
  id bigint,
  user_id bigint,
  body text
);

\copy import_notes(id, user_id, body) FROM 'notes.csv' WITH (FORMAT csv, HEADER true)
```

确认行数和关键字段后，再写入正式表。

## 迁移后检查

```sql
SELECT count(*) FROM notes;
SELECT count(*) FROM import_notes;
```

行数只是第一步，还要抽查关键查询、外键关系、唯一约束和应用最常用的页面。

## 练习题

1. 临时导出的 CSV 能当完整备份吗？
2. 迁移前为什么要检查扩展？
3. 升级数据库主版本前为什么要准备回滚方案？
4. 导入数据前为什么要确认目标表结构？

::: tip 提示
迁移不是“把数据搬过去”这么简单，版本、权限、扩展和回滚都要看。
:::

::: details 答案
1. 不能。
2. 目标库缺扩展可能导致对象创建或查询失败。
3. 升级可能遇到兼容问题，需要能退回。
4. 结构不一致会导致导入失败或数据含义错误。
:::

## 常见坑

- 把导出文件当完整备份
- 迁移前没检查扩展和权限
- 只验证行数，不验证关键查询和业务流程
- 不先导入中间表，脏数据直接进入正式表

## 先记住这三句

- 导入导出不是完整备份。
- 迁移前先查版本、权限和扩展。
- 迁移后要验证数据和关键查询。
