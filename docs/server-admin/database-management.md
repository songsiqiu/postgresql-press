# 数据库管理

数据库管理讲的是一个 PostgreSQL 实例里，数据库、模式、连接和基础维护怎么组织。新手先把它理解成“管好数据库空间和日常边界”。

## 你学完能干什么

- 能区分实例、数据库、模式和表
- 知道什么时候需要新建数据库
- 能看懂常见数据库管理命令
- 能避免把所有东西都塞进一个空间

## 常见命令

```sql
CREATE DATABASE app_demo;

ALTER DATABASE app_demo
SET timezone = 'Asia/Shanghai';

DROP DATABASE old_demo;
```

`DROP DATABASE` 会删除整个数据库，不能当成普通清理表数据的命令。

## 什么时候新建数据库

- 不同应用需要隔离数据空间
- 测试环境需要单独数据库
- 备份、恢复、权限边界需要更清楚
- 不适合只靠表名前缀区分所有业务

## 操作步骤：确认你连的是哪个库

执行高风险命令前，先确认连接目标：

```sql
SELECT current_database(), current_user, inet_server_addr(), inet_server_port();
```

查看已有数据库：

```sql
SELECT datname
FROM pg_database
WHERE datistemplate = false
ORDER BY datname;
```

删除数据库前，要确认没有连接正在使用，并确认备份和恢复方案。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 实例 | 一个正在运行的 PostgreSQL 服务 |
| 数据库 | 实例里的独立数据空间 |
| 模式 | 数据库里的分类目录 |
| 表 | 存放具体数据的结构 |

## 练习题

1. 一个 PostgreSQL 实例里可以有多个数据库吗？
2. `DROP DATABASE` 是删除一张表还是整个数据库？
3. 模式是在数据库里面，还是数据库在模式里面？
4. 测试环境适合和生产环境共用一个数据库吗？

::: tip 提示
先按“实例 > 数据库 > 模式 > 表”的层级理解。
:::

::: details 答案
1. 可以。
2. 删除整个数据库。
3. 模式在数据库里面。
4. 不适合，测试和生产应该清楚隔离。
:::

## 常见坑

- 把数据库和整个 PostgreSQL 服务混成一回事
- 用表名前缀代替清晰的数据库或模式边界
- 没确认连接目标就执行删除命令
- 把测试数据和生产数据放在同一空间
- 在错误环境里执行 `DROP DATABASE`

## 先记住这三句

- 实例里可以有多个数据库。
- 数据库里可以有多个模式。
- 删除数据库前必须确认连接目标和备份。
