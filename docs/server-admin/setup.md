# 安装与初始化

这里会整理 PostgreSQL 服务的安装、初始化和最初的配置思路。

## 你学完能干什么

- 知道安装 PostgreSQL 后还要初始化数据目录
- 能区分服务、数据目录、配置文件
- 能理解为什么不要把开发库和生产库混用

## 先理解三个东西

| 名称 | 作用 |
| --- | --- |
| PostgreSQL 服务 | 真正运行并处理请求的进程 |
| 数据目录 | 保存数据库数据和内部文件的位置 |
| 配置文件 | 控制监听地址、连接、日志等行为 |

## 初始化是什么意思

安装软件只是把程序放到机器上。初始化会创建 PostgreSQL 需要的数据目录和基础系统库。

新手可以先这样理解：

1. 安装 PostgreSQL
2. 初始化数据目录
3. 启动服务
4. 创建或连接数据库
5. 执行 SQL

## 操作步骤：确认服务可用

不同系统安装方式不同，但检查思路基本一样：

```bash
psql -h localhost -p 5432 -U postgres -d postgres
```

连上后先确认当前环境：

```sql
SELECT version();
SELECT current_database(), current_user;
SHOW data_directory;
```

如果这里连不上，不要急着建表。先确认服务是否启动、端口是否正确、认证规则是否允许当前用户连接。

## 排障场景：装好了但连不上

| 现象 | 先查什么 |
| --- | --- |
| 端口拒绝连接 | 服务是否启动、端口是否正确 |
| 提示认证失败 | 用户名、密码、认证方式 |
| 提示数据库不存在 | 连接的数据库名是否正确 |
| 本机能连远程不能连 | 监听地址、防火墙、访问规则 |

## 练习题

1. 安装 PostgreSQL 和初始化数据目录是一回事吗？
2. 数据目录主要保存什么？
3. 为什么开发库和生产库不要混用？

::: tip 提示
安装是有了程序，初始化是准备数据库自己的工作空间。
:::

::: details 答案
1. 不是。安装是准备软件，初始化是准备数据库数据目录。
2. 数据文件、系统目录和数据库运行需要的内部文件。
3. 防止测试操作影响真实数据，也方便权限、备份和配置分开管理。
:::

## 常见坑

- 装好了软件，却不知道服务有没有启动
- 连错环境，把开发操作打到生产库
- 修改配置后忘记重载或重启服务
- 初始化了新数据目录，却连接到另一个旧实例

## 先记住这三句

- 安装不等于初始化。
- 服务、数据目录、配置文件要分开理解。
- 环境一定要分清楚。
