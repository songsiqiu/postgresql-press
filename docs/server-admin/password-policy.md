# 密码与认证策略

密码和认证策略决定谁能连进数据库，以及怎样证明身份。它是安全基础，不只是“能连上就行”。

## 你学完能干什么

- 知道密码策略和认证规则要一起看
- 能理解 SCRAM、MD5、信任认证的大致差异
- 知道生产环境不能随便使用 `trust`
- 能给应用账号设置更清楚的安全边界

## 常见认证方式

| 方式 | 新手理解 |
| --- | --- |
| `scram-sha-256` | 更推荐的密码认证方式 |
| `md5` | 旧一些的密码认证方式 |
| `trust` | 不校验密码，风险很高 |
| `peer` | 依赖操作系统用户身份 |
| 证书认证 | 用客户端证书证明身份 |

实际使用时，还要结合 `pg_hba.conf` 的来源地址、数据库名和用户规则。

## 应用账号建议

- 每个应用使用单独角色
- 不用超级用户连接业务系统
- 只授予需要的权限
- 定期轮换密码或密钥
- 生产环境禁用不必要的信任认证

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 认证 | 证明你是谁 |
| 授权 | 你能做什么 |
| `pg_hba.conf` | 控制谁从哪里用什么方式连接 |
| 超级用户 | 拥有极高权限的角色 |

## 练习题

1. 认证解决“你是谁”还是“你能做什么”？
2. 生产环境适合随便用 `trust` 吗？
3. 应用账号应该使用超级用户吗？
4. 密码策略是否要和 `pg_hba.conf` 一起看？

::: tip 提示
先分清认证和授权：一个管进门，一个管进门后能做什么。
:::

::: details 答案
1. 你是谁。
2. 不适合。
3. 不应该。
4. 要。
:::

## 常见坑

- 为了省事使用 `trust`
- 应用直接用超级用户连接
- 多个系统共用同一个数据库账号
- 改了密码策略却没检查连接规则

## 先记住这三句

- 认证管谁能连进来。
- 授权管进来后能做什么。
- 生产环境不要随便信任连接。
