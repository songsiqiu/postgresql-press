# 恢复演练

恢复演练是验证备份真的能恢复。没有演练的备份，只能算“看起来存了一份文件”。

## 你学完能干什么

- 知道为什么备份必须演练
- 能设计最小恢复演练清单
- 知道演练要记录耗时和问题
- 能避免事故后才第一次恢复

## 最小演练清单

一次基础恢复演练至少确认：

- 能拿到备份文件
- 能拿到需要的 WAL
- 能在隔离环境启动恢复
- 能验证关键表和关键数据
- 能记录恢复耗时
- 能清楚谁负责下一步

## 演练不是演戏

恢复演练要尽量接近真实事故，但不能影响生产。可以用隔离机器、测试环境或专门恢复环境。

每次演练后都要记录：

- 哪一步卡住
- 缺了什么权限或文件
- 恢复用了多久
- 文档哪里不清楚

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 备份 | 保存数据副本 |
| 恢复 | 用备份把数据库拉起来 |
| 演练 | 提前验证恢复流程 |
| RTO | 业务能接受的恢复耗时 |

## 练习题

1. 只做备份不演练可靠吗？
2. 恢复演练应该在生产库上直接做吗？
3. 演练后要不要记录耗时？
4. 关键数据恢复后是否需要验证？

::: tip 提示
备份是否可靠，要靠恢复演练证明。
:::

::: details 答案
1. 不可靠。
2. 不应该，应该在隔离环境做。
3. 要。
4. 需要。
:::

## 常见坑

- 备份脚本每天成功，但从没恢复过
- 没有记录恢复耗时
- 演练环境和生产差异太大
- 恢复后没有验证业务关键数据

## 先记住这三句

- 备份要靠恢复证明。
- 演练要记录问题和耗时。
- 事故前演练，事故时才不慌。
