# SSL/TLS 连接

SSL/TLS 用来保护客户端和 PostgreSQL 服务器之间的网络连接。它不是权限系统，但能减少连接过程被窃听或篡改的风险。

## 你学完能干什么

- 知道 SSL/TLS 解决的是传输安全问题
- 能理解服务器证书、私钥和客户端校验的关系
- 知道哪些配置要和 `pg_hba.conf` 一起看
- 能避免把加密连接和数据库权限混成一件事

## 基本思路

启用 SSL/TLS 通常要准备：

- 服务器证书
- 服务器私钥
- PostgreSQL 侧的 SSL 配置
- 客户端连接参数
- `pg_hba.conf` 中允许或要求 SSL 的规则

一个常见连接参数是：

```text
sslmode=require
```

它表示客户端要求使用 SSL 连接。更严格的校验还会涉及证书验证和主机名验证。

## 操作步骤：确认当前连接是否使用 SSL

```sql
SELECT ssl, version, cipher
FROM pg_stat_ssl
WHERE pid = pg_backend_pid();
```

如果 `ssl` 是 `false`，说明当前连接没有使用 SSL。  
如果业务要求加密连接，要同时检查客户端 `sslmode` 和服务端访问规则。

## 和权限的关系

SSL/TLS 只解决“连接路上是否加密、是否校验证书”的问题。

角色权限仍然要靠：

```sql
GRANT SELECT ON TABLE orders TO app_user;
```

也就是说，加密连接不能代替授权。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| SSL/TLS | 保护网络连接的加密协议 |
| 证书 | 用来证明服务器身份的一类文件 |
| 私钥 | 服务器必须保护好的密钥文件 |
| `sslmode` | 客户端连接时的 SSL 要求 |
| `hostssl` | `pg_hba.conf` 里只匹配 SSL 连接的规则 |

## 练习题

1. SSL/TLS 主要保护的是数据存储还是网络传输？
2. 加密连接能不能替代 `GRANT` 授权？
3. `sslmode=require` 表示客户端希望什么？
4. 私钥文件应该公开给客户端吗？

::: tip 提示
先分清“路上加密”和“进库后能做什么”，这是两个问题。
:::

::: details 答案
1. 网络传输。
2. 不能。
3. 要求使用 SSL 连接。
4. 不应该。
:::

## 常见坑

- 以为开了 SSL 就不需要权限控制
- 证书和私钥权限过宽
- 客户端只要求加密，却没有按需要做身份校验
- 改了 `pg_hba.conf` 后忘记重新加载配置
- 以为连接串写了 `sslmode` 就一定已经按预期加密

## 先记住这三句

- SSL/TLS 保护连接路上的数据。
- 权限仍然要靠角色和授权控制。
- 证书、私钥和连接规则要一起检查。
