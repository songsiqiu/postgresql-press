# 复制槽

复制槽用来让 PostgreSQL 知道哪些 WAL 还需要保留给复制使用。它能保护复制过程，也可能因为长期不用而占满磁盘。

## 你学完能干什么

- 知道复制槽和 WAL 保留有关
- 能理解物理复制槽和逻辑复制槽的大致用途
- 知道不用的复制槽要及时清理
- 能把复制延迟和磁盘增长联系起来排查

## 为什么需要复制槽

复制客户端如果暂时断开，主库可能继续产生 WAL。复制槽可以告诉主库：这些 WAL 还不能删，副本或订阅端回来后还要用。

这很有用，但如果复制客户端长期不回来，WAL 会越积越多。

## 常见查看

```sql
SELECT slot_name, slot_type, active
FROM pg_replication_slots;
```

这能看到复制槽名字、类型和是否活跃。

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 复制槽 | 保留复制所需 WAL 的机制 |
| 物理复制槽 | 常用于流复制 |
| 逻辑复制槽 | 常用于逻辑复制和订阅 |
| 活跃 | 当前有客户端在使用 |
| WAL 积压 | 复制没消费导致 WAL 持续保留 |

## 练习题

1. 复制槽主要和什么日志保留有关？
2. 不用的复制槽长期存在可能造成什么问题？
3. 查看复制槽可以查哪个系统视图？
4. 逻辑复制槽常用于哪类复制？

::: tip 提示
看到 WAL 目录增长，要记得检查复制槽是否长期不活跃。
:::

::: details 答案
1. WAL。
2. WAL 无法清理，磁盘可能被占满。
3. `pg_replication_slots`。
4. 逻辑复制。
:::

## 常见坑

- 测试复制槽用完不删
- 只看复制是否断开，不看 WAL 是否积压
- 不监控复制槽活跃状态
- 把复制槽当成备份

## 先记住这三句

- 复制槽会保留 WAL。
- 不活跃的复制槽可能占满磁盘。
- 复制槽不是备份。
