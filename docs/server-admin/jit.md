# JIT 即时编译

JIT 是 PostgreSQL 在部分复杂查询中使用的即时编译能力。新手不需要一开始调它，但要知道它为什么会出现在执行计划里。

## 你学完能干什么

- 知道 JIT 不是索引，也不是缓存
- 能看懂执行计划里出现的 JIT 信息
- 知道小查询不一定适合打开 JIT

## 可运行例子

查看当前会话是否开启 JIT：

```sql
SHOW jit;
```

看执行计划时，如果出现 `JIT` 段落，说明数据库认为某些表达式、过滤或计算可能值得即时编译。

```sql
EXPLAIN
SELECT sum(amount)
FROM orders
WHERE created_at >= date '2026-01-01';
```

## 排障步骤：看到 JIT 段落

1. 先确认查询是否复杂、是否包含大量表达式计算。
2. 看总耗时里 JIT 编译时间占比。
3. 对短小高频查询，不要只因为出现 JIT 就认为更好。
4. 对复杂分析查询，再结合执行计划评估是否有收益。

临时对当前会话关闭 JIT 可以这样观察差异：

```sql
SET jit = off;
EXPLAIN ANALYZE
SELECT sum(amount)
FROM orders
WHERE created_at >= date '2026-01-01';
```

## 容易混淆的词

| 词 | 区别 |
| --- | --- |
| JIT | 把部分执行过程即时编译，减少复杂计算开销 |
| 索引 | 帮数据库更快定位数据 |
| 缓存 | 复用已经读到内存里的数据 |
| 执行计划 | 数据库准备怎么执行 SQL |

## 练习题

1. JIT 是不是一种索引？
2. 用什么命令可以查看当前会话的 `jit` 参数？
3. 为什么很短的小查询不一定适合 JIT？

::: tip 提示
JIT 的收益来自减少复杂计算成本，但它本身也有启动成本。
:::

::: details 答案
1. 不是。
2. `SHOW jit;`
3. 因为即时编译也要花时间，小查询可能还没赚回这部分成本。
:::

## 常见坑

- 看到 JIT 就以为查询一定更快
- 把 JIT 当作索引优化的替代品
- 没看执行计划就盲目开关参数
- 不比较开关前后的实际计划和耗时

## 先记住这三句

- JIT 主要服务复杂查询里的计算成本。
- 小查询不一定适合 JIT。
- 先看执行计划，再讨论是否调整。
