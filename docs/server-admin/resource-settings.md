# 资源参数

资源参数决定 PostgreSQL 如何使用内存、并发和后台维护能力。新手不需要一开始就会调优，但要知道它们不是随便越大越好。

## 你学完能干什么

- 知道资源参数会影响内存和并发
- 能理解常见参数的大致用途
- 知道调参数前要先看负载和证据
- 能避免照抄别人的配置

## 常见参数

| 参数 | 新手理解 |
| --- | --- |
| `shared_buffers` | PostgreSQL 自己管理的共享缓冲区大小 |
| `work_mem` | 排序、哈希等操作可用的单次工作内存 |
| `maintenance_work_mem` | 建索引、VACUUM 等维护操作可用内存 |
| `max_connections` | 允许同时存在的最大连接数 |
| `effective_cache_size` | 给规划器参考的可用缓存估计 |

这些参数相互影响。比如 `work_mem` 不是全局只用一次，它可能被很多连接、很多操作同时使用。

## 调整前先看什么

- 当前连接数和活跃 SQL
- 是否有大量排序或哈希溢出到磁盘
- 表和索引大小
- 机器内存和其他服务占用
- 真实业务高峰

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 全局参数 | 影响整个实例的配置 |
| 会话参数 | 可以在连接或事务中调整的配置 |
| 工作内存 | 单个操作可用的内存，不是总内存 |
| 规划器估计 | 帮数据库选择执行计划的参考值 |

## 练习题

1. `work_mem` 是全库只用一次的内存吗？
2. `max_connections` 越大越好吗？
3. 调资源参数前应该先看负载证据吗？
4. 建索引这类维护操作可能和哪个内存参数有关？

::: tip 提示
资源参数要按机器、数据量和业务负载一起看。
:::

::: details 答案
1. 不是，它可能被多个连接和多个操作同时使用。
2. 不是。
3. 应该。
4. `maintenance_work_mem`。
:::

## 常见坑

- 直接复制别人的生产配置
- 把 `work_mem` 调很大却忽略并发数量
- 只看总内存，不看连接和操作数量
- 调参后不观察效果

## 先记住这三句

- 资源参数影响整体稳定性。
- 不是越大越好。
- 调参前先看证据。
