# 审计与留痕

审计的目标是回答“谁在什么时候做了什么”。它不是单纯把日志开到最大，而是按风险选择需要记录的行为。

## 你学完能干什么

- 知道审计和普通排障日志的区别
- 能判断哪些行为应该留痕
- 知道日志量和隐私风险需要一起考虑
- 能给生产库设计基本审计清单

## 常见要记录的行为

- 登录成功和失败
- 角色和权限变更
- 表结构变更
- 高风险数据修改
- 管理员操作
- 备份、恢复、导入导出操作

这些内容可以通过 PostgreSQL 日志、应用日志、数据库扩展和运维平台组合完成。不要把所有审计压力都压到一个地方。

## 一个审计清单

| 问题 | 要看什么 |
| --- | --- |
| 谁登录了数据库 | 连接日志、认证日志 |
| 谁改了权限 | DDL 或权限变更记录 |
| 谁导出了数据 | 应用操作日志、数据库命令记录 |
| 谁删了重要数据 | 业务审计表、应用日志、数据库日志 |

## 容易混淆的词

| 词 | 新手解释 |
| --- | --- |
| 排障日志 | 为了定位错误和性能问题 |
| 审计日志 | 为了追溯操作责任和安全事件 |
| 留痕 | 让关键行为之后能被查到 |
| 脱敏 | 避免日志里暴露敏感数据 |

## 练习题

1. 审计最核心要回答哪三个问题？
2. 普通错误日志能完全替代审计吗？
3. 为什么不能把所有 SQL 参数都无脑打到日志里？
4. 权限变更是否属于高价值审计对象？

::: tip 提示
审计先从高风险动作开始，不要一上来记录所有细节。
:::

::: details 答案
1. 谁、什么时候、做了什么。
2. 不能。
3. 可能泄露密码、手机号、身份证号等敏感信息，也会放大日志量。
4. 属于。
:::

## 常见坑

- 只记录错误，不记录关键成功操作
- 日志里写入过多敏感信息
- 发现事故后才想起没有留痕
- 日志没有集中保存，机器出问题后一起丢失

## 先记住这三句

- 审计是为了事后能追溯。
- 先记录高风险动作。
- 日志越多不一定越安全。
