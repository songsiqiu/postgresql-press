# 配置参数

配置参数决定 PostgreSQL 怎么监听连接、怎么使用资源、怎么记录日志。新手不需要一开始背所有参数，先知道它们分成几类。

## 你学完能干什么

- 能区分连接配置、资源配置、日志配置
- 知道改配置前要确认影响范围
- 知道有些配置需要重启，有些可以重载

## 配置大致分几类

| 分类 | 常见问题 |
| --- | --- |
| 连接 | 监听哪些地址、允许多少连接 |
| 内存 | 查询、排序、缓存能用多少资源 |
| 日志 | 记录哪些日志、日志放哪里 |
| 复制 | 主从复制和归档相关设置 |
| 自动维护 | 统计信息、清理旧版本 |

## 改配置前先问

1. 这个参数解决什么问题？
2. 影响整个实例，还是只影响当前会话？
3. 需要重启还是重载？
4. 有没有回滚方案？

## 练习题

1. 连接数属于哪类配置？
2. 改配置前为什么要知道是否需要重启？
3. 日志配置能帮助解决什么问题？

::: tip 提示
配置不是越大越好。数据库资源配置要和机器、业务、连接池一起看。
:::

::: details 答案
1. 连接配置。
2. 重启可能影响服务可用性，需要安排窗口。
3. 帮助定位错误、慢查询、连接和权限问题。
:::

## 常见坑

- 看到网上建议就直接套参数
- 把连接数调很大，却没有看机器资源和连接池
- 改完配置不知道是否生效

## 先记住这三句

- 配置要服务具体问题。
- 改配置前先确认生效方式。
- 参数不是越大越好。
