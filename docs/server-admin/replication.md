# 复制与高可用

复制和高可用解决的是数据库故障时怎么减少影响。它们很重要，但不能替代备份。

## 你学完能干什么

- 知道复制大概解决什么问题
- 能区分读扩展、容灾和备份
- 知道高可用方案需要演练

## 复制是什么

复制可以让一个 PostgreSQL 实例的数据变化同步到另一个实例。常见形式是主库负责写入，从库接收变化。

它常用于：

- 故障切换
- 读请求分担
- 报表或分析隔离
- 灾备准备

## 高可用不等于备份

高可用关注“服务尽量不中断”。备份关注“数据能恢复”。

如果误删了一张表，复制可能很快把这个误删同步到从库。此时仍然需要备份来恢复。

## 演练很重要

高可用方案不能只停留在架构图上。要定期演练：

- 主库故障怎么切换
- 切换后应用怎么连接
- 原主库恢复后怎么处理
- 数据是否一致

## 练习题

1. 复制能替代备份吗？
2. 从库常见用途有哪些？
3. 为什么高可用方案需要演练？

::: tip 提示
把高可用理解成“少停机”，把备份理解成“能找回”。
:::

::: details 答案
1. 不能。
2. 故障切换、读请求分担、报表隔离、灾备。
3. 故障时步骤复杂，不演练就不知道是否真的能切换成功。
:::

## 常见坑

- 以为有从库就不用备份
- 只画架构图，从不做切换演练
- 忽略应用连接地址和故障切换流程

## 先记住这三句

- 复制不是备份。
- 高可用要靠演练证明。
- 故障切换要同时考虑数据库和应用。
