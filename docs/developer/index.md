# 开发者内容

这一页保留为开发相关内容的总入口。现在开发内容已经拆到几个更清楚的主线里。

## 你学完能干什么

- 知道应用开发、SQL 能力、服务端编程分别去哪里看
- 能区分“应用怎么连数据库”和“数据库内部怎么写逻辑”
- 能找到 JSON、全文检索、函数、触发器这些内容

## 推荐入口

| 你想做什么 | 去哪里 |
| --- | --- |
| 应用连接数据库 | [客户端接口](/client-interfaces/) |
| 学 SQL 和 JSON 能力 | [SQL 语言](/sql-language/) |
| 写函数、触发器、扩展 | [服务端编程](/server-programming/) |
| 查数据类型和函数 | [参考手册](/reference/) |
| 理解为什么会慢或等待 | [内部原理](/internals/) |

## 开发者学习顺序

1. 先学 [SQL 核心](/guide/sql)
2. 再学 [客户端接口](/client-interfaces/)
3. 然后补 [SQL 语言](/sql-language/)
4. 最后按需要看 [服务端编程](/server-programming/) 和 [内部原理](/internals/)

## 练习题

1. 应用里处理用户输入 SQL 参数，应该优先看哪个板块？
2. 想写触发器，应该看哪个板块？
3. 想查 `jsonb` 怎么用，应该看哪个板块？

::: tip 提示
开发者不要一开始就钻服务端编程。先把 SQL、连接、事务边界学稳。
:::

::: details 答案
1. 客户端接口。
2. 服务端编程。
3. SQL 语言里的 JSON 与全文检索，或参考手册里的数据类型。
:::

## 常见坑

- 把所有逻辑都写在数据库触发器里
- 应用层直接拼接 SQL
- 不理解事务边界就做多表修改

## 先记住这三句

- 应用开发先管好连接、参数和事务。
- 数据库服务端编程要克制使用。
- 复杂能力要服务真实问题。
